## 0 Stop the line

Three things are true at `76ace90` and are not true in any prior handoff. They are why this report leads with a stop-the-line rather than a summary.

**0.1 — One unauthenticated request can stall the whole deployment, and no flag mitigates it.**
`app/utils/url_validator.py:30` runs `socket.getaddrinfo(hostname, None)` — a blocking, un-cancellable C call — inside a synchronous `def` that is called *inline* from six `async` handlers on `/api/v1/url/*` (`url_routes.py:91,112,148,175,197,216`), none of which has an auth dependency. **Measured**, not argued: with the resolver stubbed at 3.0 s, a 10 ms asyncio ticker advanced **0 times** during the call, and an ASGI repro starved a control route on the same loop for the full 3.0 s. Against a real black-holed host the finder measured **11.07 s** for one call. Single-worker uvicorn, one event loop, `10/minute` keyed on the shared Railway edge IP — i.e. deployment-wide. This is `CR-SECURITY-05`, the same defect the load lane filed as `LS-REQUEST-PATH-BLOCKING-01`, which the orchestrator rated **P0**. It is also on the **price path** (`price_service.py:14126/:14147` inside `curl_fetch_html_same_site`, and `shopify_pdp_service.py:284`), per URL and per redirect hop. **It must land before `#114` re-keys the limiter**, because re-keying raises the per-caller ceiling on exactly this route.

**0.2 — Two individually-benign defects compose into an unauthenticated production-credential disclosure.**
`admin_routes.py:37` compares `X-Admin-Key` with `hmac.compare_digest` on `str`, which raises `TypeError` on any non-ASCII character; Starlette latin-1-decodes header bytes, so one high byte reaches it. The raising frame's locals are `{x_admin_key, expected}` and **`expected` is `ADMIN_API_KEY`**. A second-vote agent reproduced this through the *real* pipeline (real `init_sentry()`, capturing transport, TestClient, real `verify_admin_key`): **HTTP 500 and an event carrying 99 sentinel sites**, including the admin key verbatim at `frames[19].vars.expected`, the caller JWT at `.request.data.access_token`, and `?token=<full JWT>` surviving in `request.query_string` while `q=` beside it is redacted — falsifying the scrubber's own docstring at `sentry_service.py:29-31`. `SENTRY_DSN` is set on the prod `web` service. Neither agent fired it at prod, deliberately, because firing it *is* the exfiltration. `CR-SECURITY-04` × `CR-SECURITY-03`. **Treat `ADMIN_API_KEY` as possibly already disclosed and rotate it** — nobody could check whether such a 500 has already fired.

**0.3 — A paid egress path is armed in production and documented as dormant, with its own budget gate switched off.**
`CLAUDE.md:328` says `ENABLE_BRIGHTDATA_FALLBACK` + `BRIGHTDATA_API_KEY` + `BRIGHTDATA_ZONE` are "default OFF/unset — dormant". `baseline/railway-web-vars.txt` has all three set on **both** `web` and `price-warmer` (`=true`, `serp_api1`, key present) — and `_brightdata_enabled()` requires exactly those three. ## 3 What could not be known

Recorded so a later session does not mistake absence of evidence for evidence of absence.

1. **No live compare was possible.** OpenAI returns `429 insufficient_quota`; the Serper balance is -50. Every orchestrator-level claim is from code read, unit-level execution against exported `76ace90` trees, recorded payloads and the `_proof` corpus — **not** from `compare_from_text` end-to-end. Findings `CR-DELTA-CORRECTNESS-04/06/07` and the `home_routes` rows are reasoned and unit-reproduced, never driven through the real orchestrator.
2. **The local pip environment is OFF-LOCK by 48 packages** (fastapi 0.115.0 vs 0.141.1, starlette 0.38.6 vs 1.6.0, pydantic 2.7.0 vs 2.13.4, sentry-sdk 2.54.0 vs 2.68.1, httpx 0.27.0 vs 0.28.1). No local pytest result certifies CI or prod on any framework-introspection or SDK-shape question. Where it mattered, agents read the **pinned wheel** instead (httpx 0.28.1 transport construction; postgrest 2.31.0's `DEFAULT_POSTGREST_CLIENT_TIMEOUT = 120`) and CI claims were read off the **real CI job log** for `76ace90` (run 33651445359).
3. **Railway/Linux milliseconds are unmeasured.** Dev-box timings for `load_verify_locations`, `create_client` and `extract_price_from_html` are Windows numbers; the **counts** transfer, the ms do not. **Upstash RTT from Railway has still never been measured** — the same gap M18 recorded. A `py-spy`/`cProfile` run inside `railway ssh` closes it.
4. **No load or concurrency test was run** (the brief forbids it). Every "N concurrent requests" consequence is MODELLED from measured per-request counts.
5. **The live database's index and policy state is unverifiable from here.** `pg_indexes`, `pg_policies`, `pg_catalog` and `information_schema` are not reachable through PostgREST (measured); the plan media type is refused (`PGRST107`); no read-only RPC exposes the catalog; and there is no `DATABASE_URL` in `.env`. **Column** claims are measured (42703/200 per column); **index and RLS-policy** claims are DDL-derived. Two proven single-request exploits were **deliberately not fired**: the anon `POST /rpc/delete_user_cascade` (destructive) and the non-ASCII `X-Admin-Key` request (firing it *is* the exfiltration this report describes). Residual doubt on the delete chain is ~0.02.

What `.mcp.json` plus 13 enabled plugins add has to be read off `/context` in a live interactive session started from the repo.
8. **The SSE streaming generator was never driven end-to-end** — only the sync `compare_from_text` path. Its per-event Redis/analytics writes and the `_tail_residual()` arithmetic are un-instrumented. The performance lane names this as its own biggest gap.
9. **54 of 68 routes were never driven through a harness**, including all 20 `/admin/*` (which contain several unbounded full-table scans nobody has costed), all six `/url/*`, `/image/identify`, `/share/*`, `/referrals/*`, `/feedback`+`/events`, and `/text/prices` itself.

The `HistoryScreen` +373/−272, `api.ts` +322/−67 and `onboardingDraft.ts` deltas were not reviewed here — and the standing two-lever fact applies to everything client-side: **the phone OTA `97b5f15` predates all four M21 waves**, so no mobile finding may be called fixed-for-users until `eas update --branch preview` lands from ≥`76ace90`.
11. **Dead code was analysed at function granularity.** A 1,949-LOC function counts as fully live if it is called once, so `_get_price` almost certainly contains large dead regions nobody enumerated. Class **methods**, module-level **constants** (298 in `price_service` alone), dead SQL, dead data files and `landing/`/`cloudflare-workers/` were not swept.
12. **Whether the five runner-less cron scripts are executed by some out-of-repo scheduler** (a personal crontab, a manual `railway run`) could not be proven — only that no Railway service, no GitHub Actions schedule, no `Procfile` and no `railway*.json` invokes them.

14. **GitHub rulesets were not checked** — only the classic `branches/main/protection` endpoint. A ruleset could in principle add protections that endpoint does not report.
