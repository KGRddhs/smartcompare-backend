Follow-up of PR #207 (merged as 4cff9bc1): the process-wide network guard `tests/_netguard.py` now BLOCKS every non-loopback attempt (`NetworkBlocked`, an `OSError` subclass) and records it per node, and `scripts/netguard_ratchet.py` fails CI only on a NEW node whose attempt class includes `egress`. The blocked attempt is raised INTO the code under test, so fail-open code takes its offline branch and the test still passes: today an attempt is a recorded fact, not a failure.

**The baseline (`tests/.network_attempt_baseline.txt`, 205 lines = 184 chunk nodes + 21 pin nodes).** Class mix of the 184: egress 79, sentinel 94, sentinel+egress 11 - so **90 baseline nodes carry a real egress attempt**. Measured at base 61585c58 by target class (196 nodes then; PR #207 removed 12 and added 0): 69 api.openai.com, 106 `*.invalid` sentinels (95 exclusively), 28 curl_cffi retailer fetches (noon, Shopify `products.json`, algolia, unbxd, footlocker, sharafdg), 8 SSRF literals, 6 example.com. Top files: test_two_input_shape 20, test_streaming 16, test_text_error_envelope_no_raw_exception 14, test_personalization 10, test_flush_live_price_key 9, test_w49_extraction_catch_redaction 8, test_category_selection 7, test_http_400_cap_cut_mapping 7.

**The campaign (class by class, api.openai.com first).** For each egress-class baseline node: find the code path that reaches the network (an unmocked OpenAI client, an unmocked adapter fetch, a validator resolving a real host), mock or stub it at the right seam, re-run the file under the guard, confirm `[netguard] blocked 0` for that node, and REMOVE the node from the baseline (`scripts/netguard_ratchet.py REPORT BASELINE --write` after a full-tier run, keeping the one timing-dependent node documented in the PR). When the egress class is empty, flip the guard's policy so a real egress attempt FAILS the test instead of being recorded (a new `--strict` mode or a marker), which is the end state #184 asked for.

**Also in scope (small items from the PR's follow-ups):**
- Per-file guards (`socket_guard` in tests/test_w49_extraction_catch_redaction.py, `_no_network` in the W4-4 file, `_zero_network` in tests/test_retro_w0_4.py) install over the process guard with monkeypatch, so the attempts they catch never reach the report; make them delegate to `tests._netguard.NetworkBlocked` (or drop them) so the ratchet sees everything.
- A child pytest process in the CI-order set inherits `QAREN_NETGUARD_REPORT` and overwrites the report mid-run (the parent rewrites it at session end, so the final report is correct); the child should drop the variable.
- `_price_service_globals` in tests/test_w49_extraction_catch_redaction.py can be simplified now that #185's cycle proof runs in a subprocess.
- Optional one-line tightening of the CI ratchet pin to reject `$RUNNER_TEMP` spellings on the test step's `env:`.

**Stated limits to keep in mind (from the PR):** attribution is by the process-wide current test, not by thread (a late thread lands on the next test); a baseline node that does not attempt in a given run only shrinks the set (exit 0 with a shrink line); a cold tiktoken cache on a local box shows the two in-test loader sites as NEW egress nodes (warm once with the command in the skip message; CI's warm step does it).
