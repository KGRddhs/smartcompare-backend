## Context

MYEZ (FastAPI backend `app/`, Expo client `SmartCompareApp/`; repo KGRddhs/smartcompare-backend) compares products for GCC shoppers. Build 1.0.0 (3) is in Apple App Review against the live backend. The tester audit (session 80) and the owner's own use show the same root problem: the data layer is a live scrape-and-search pipeline (Serper + GPT-4o-mini + curl_cffi + paid render tiers) that misses prices, images and identity on a large share of compares, costs money per compare, and cannot reach walled sites.

The owner's decision (2026-10-22): rebuild the data and AI layer around (1) Anthropic (Claude Haiku 5.5 default, Sonnet 5.5 where needed, server web_search + vision), (2) an owned, auto-growing product knowledge base and merchant registry that becomes the primary source, with every user request enriching it, (3) fragrances only live (skincare, makeup = coming soon with tap tracking; other six hidden), (4) a critique-and-feedback loop so the brain improves with use, (5) honest UI (no fabricated shopper counts/percentages), (6) faster app and faster compares, (7) per-platform share flow, (8) login/sign-up rate limits and 3 compares/day/device.
