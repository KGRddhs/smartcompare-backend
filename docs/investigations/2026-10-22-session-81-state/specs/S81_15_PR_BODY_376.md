## What the flags do

- `ENABLE_MERCHANT_REGISTRY_DB` (+ `MERCHANT_REGISTRY_MEMO_SECONDS` 600 [300..900], `MERCHANT_REGISTRY_READ_TIMEOUT_SECONDS` 5 [1..30], `MERCHANT_REGISTRY_MAX_STALE_SECONDS` 3600 [900..21600]): the router's registry comes from `kb_merchants` through a per-process memo (`app/services/merchant_registry.py`). One paged read (`status in (live, blocked)`, `.order('host')`, 500-row pages) in a background task via `asyncio.to_thread` under `wait_for`; callers never await it; the task is created OUTSIDE the memo lock in a FRESH `contextvars` context (F1-12), so its log lines never carry a request's context. Two sets (R-S15-1): SELECTION (`source_router.registry_rows`, read only by `_routable_registry`: the selectors, `score_source`, `source_usage`, `is_render_only_domain`) = live, not-denied rows; LOOKUP (`registry_lookup_rows`, read by `_registry_row_for_host` and the three direct readers) keeps blocked and denied rows, so a cron-blocked host keeps its tier, currency and global-tier refusals. sha256 snapshot over the decode columns + the catalog flag. Failures never raise: code registry until a good load, then the last good list up to max stale; one WARNING per window by reason. Flag OFF: `SOURCE_REGISTRY` by identity, no read, no task, no log.
- `ENABLE_ROBOTS_REGISTRY_CRON` (+ `ROBOTS_CRON_MAX_HOSTS` 500 [1..5000], `ROBOTS_CHALLENGE_PARK_DAYS` 7 [1..30] (a fraction 0 < v < 1 clamps to 1, F1-23), `ROBOTS_DUE_SLACK_SECONDS` 3600 [0..21600], read once per run (F1-3)): `app/services/robots_registry.py` + `scripts/cron_robots_registry.py` (a new Railway cron service, `railway.robots.json`). Daily: a host is due when its stored `robots.next_reread` is at or before the run start + the slack (the belt for cron-start jitter); `next_reread` is computed from the run start (+ 24 h, the RFC 9309 cache bound), so a run of any length under 24 h re-reads every host the previous daily run read; once the first pass is done no record is older than 24 h + one run (RB15-2; measured 40 / 40 on four runs of 200 min, where a per-read `next_reread` read 40 / 12 / 40 / 12). Sequential, polite (max(Crawl-delay <= 60, 2 s)), QarenBot UA (`robots_eval.QARENBOT_UA`), no impersonation, redirects by hand (`allow_redirects=False`) with the SSRF check on every hop; robots read from the probe origin (the sample PDP origin only when it is the row host or a subdomain of it; a cross-site or PARENT-host sample, the three `*.salla.sa` stores, is listed under `robots.other_origins`, F1-4); every body capped at 3,000,000 BYTES before decoding (F1-11); `default_validate` answers with a reason: a refused name or address is SSRF (`health.ssrf` initial / `ssrf_redirect` on a hop), a resolver failure is `robots_unreadable` with `health.dns = unresolved`, never an SSRF label (F1-13); fail-closed `decide_robots`; the D14 record (rules + probed, frozen by the fixture; additive `rules_truncated` / `other_origins` only when relevant, F1-27); transitions (live -> blocked robots_disallow / robots_unreadable / challenge / ssrf_redirect, Option A rejoin, candidates never blocked, promotion gates robots -> tos -> pdp -> platform); Option C residential rider (a residential / operator record < 30 days is never replaced; its `next_reread` moves to the lapse day, F1-14); conditional updates on `updated_at`; every deny_hosts host refused by name before any request at every entry point (the cron run, the seed's `--hosts` read, `--classify`; F1-10).
