## 0. What the unit does

1. Rule 1, pre-consume, $0: a positive NON-fragrance product-type word in the query (EN or AR, from the new lexicon file) with no fragrance product-type word -> HTTP 400 code `CATEGORY_NOT_LIVE` (additive `category`, `categories_live`), before the preferences read, the budget read and the credit consume; nothing is consumed, parsed, fetched or refunded; one INFO metric line.
2. Refusal budget, pre-consume: every request that will consume (rules 2 and 3) first reads the per-subject refusal counter (subject = the S81-05 device key when the X-Device-Fingerprint header is bound, else the account id); at or past `REFUSAL_DAILY_BUDGET` -> HTTP 429 code `CATEGORY_NOT_LIVE`, `scope: "refusal_daily"`, `retry_after` (-> `retry_after_seconds` + `Retry-After` through the existing W1-9 block), `resets_at`, never billed (no prefs read, no consume).
3. Rule 2 and rule 3, post-consume: the request consumes and parses exactly as today; RIGHT AFTER `_resolve_pair_category` and BEFORE the behaviour-profile task and `_fetch_product_data`, the orchestrator decides the pair category WITHOUT the client chip (measured hole, 1.4): a fragrance detection proceeds; an "other" detection proceeds only with fragrance evidence from the query (rule 2: a concentration / form / house hit, two note hits, or a KB match through the seam); a blind explicit or vision pair without evidence is classified by the existing A2b classifier through the S81-06 router (the "residue classifier", rule 3); anything else is refused with the same code: the counter is incremented (one Lua EVAL: INCR + EXPIREAT the next reset + 1 h), the route's EXISTING failure arm refunds the credit (the S81-09 stash carries the device key), and no Serper / scraper / Firecrawl call is made.
4. ### 2.2 The lexicon file data/fragrance_lexicon.json (new data file)

Schema (exact top-level keys, `version` int 1):
```
{"version": 1,
```

### 2.3 Normalisation and matching (pure functions; Q2)

`normalize(text) -> list[str]` (tokens): NFKC; `casefold`; strip Arabic diacritics U+064B..U+0652 and U+0670 and the tatweel U+0640; alef forms U+0622 / U+0623 / U+0625 -> U+0627; ta marbuta U+0629 -> U+0647; alef maqsura U+0649 -> U+064A; Arabic-Indic digits U+0660..U+0669 and U+06F0..U+06F9 -> ASCII digits; every char that is not a letter or digit (unicodedata category L* or N*) -> a space; split on whitespace; then per token strip ONE leading Arabic article from (U+0648 U+0627 U+0644 "wal", U+0628 U+0627 U+0644 "bal", U+0643 U+0627 U+0644 "kal", U+0641 U+0627 U+0644 "fal", U+0644 U+0644 "lil", U+0627 U+0644 "al") when the remainder keeps at least 2 letters. A bare leading waw (U+0648) is NOT stripped ("ward", rose, starts with it). Terms are normalised with the same function (a term is its token sequence).

`scan(texts) -> ScanResult` over the concatenated token stream of every text (query, or the vision names): every lexicon term (both sections) is tried longest-first (by token count, then by character length, then lexicographic for determinism); a term matches at a position where its token sequence equals the stream's tokens and none of those tokens is already masked; a match masks its tokens. Result fields:
- `non_fragrance`: ordered list of (category, term) for every non-fragrance match, in stream order;
- `fragrance_type`: True iff a concentrations or forms term matched;
- `houses`: count of house matches; `notes`: number of DISTINCT note terms matched;
- `evidence`: `fragrance_type or houses >= 1 or notes >= 2` (the KB seam adds to it, 2.4).

Matching is whole-token only: "iphone" never matches "phone"; "smartphones" matches only because the term "smartphones" exists. Longest-first masking means "hair mist" (a fragrance form) consumes "hair" before the haircare term "hair" is tried, and "body lotion" is consumed as skincare before "lotion".

`evaluate(texts, *, subject) -> GateDecision` (frozen dataclass: `outcome` "refuse" | "proceed", `category` (canonical str or None), `evidence` bool, `subject` (2.6) or None):
- RULE 1: `non_fragrance` non-empty AND `fragrance_type` False -> outcome "refuse", category = the category of the FIRST non-fragrance match in stream order. A house or note hit never rescues a rule-1 hit (Q2: product type over brand, PRODUCT_PARSER_PROMPT :136).
- otherwise -> "proceed" with `evidence` as scanned. A double product-type positive ("perfume" and "lipstick") proceeds (the brief's Q2 default) and is settled post-resolve.

### 2.6 The refusal budget (Q3)

Subject (`budget_subject(user) -> Optional[Tuple[str, str]]`, function-local `request_context` import): `fp = request_context.device_fingerprint()`; `dk = request_context.device_key(fp) if fp else None`; dk -> `("dev", dk)`; else a user with an id -> `("acct", user_id)`; else None (anonymous without a device key: no budget read, no INCR; in production anonymous compares are 401 under ENABLE_COMPARE_AUTH_REQUIRED, L7). The raw fingerprint never appears in a key, an argument or a log.

Keys (two literal f-strings, so the 043 census sees the per-user one, 4.1 E1): `f"refusal:daily:dev:{device_key}:{day}"` and `f"refusal:daily:acct:{user_id}:{day}"`, `day` = `usage_service._usage_window(now)[0]` formatted `%Y-%m-%d` (S81-09 contract: the Asia/Riyadh day under ENABLE_RIYADH_RESET, else the UTC day; one clock read `now = datetime.now(timezone.utc)` per call).

Read (`budget_state_async(subject) -> Optional[Tuple[int, str]]`): one GET through the #115 dispatch (`asyncio.to_thread` iff `cache_service._redis_offload_enabled()`, the module-level symbol referenced in both branches, usage_service :286-312 pattern); `count >= refusal_daily_budget()` -> `(retry_after, resets_at)`, else None. `retry_after = ceil((next_reset - now).total_seconds())` clamped to 1..86400 (int); `resets_at = next_reset` rendered in the reset zone with `isoformat(timespec="seconds")` ("+03:00" under the S81-09 Riyadh flag, "+00:00" otherwise), the S81-09 2.5 formulas (a drift pin R43 against S81-09's own 429 values after the rebase). `redis_client` None -> None silently; a raising GET or a non-int reply -> None + ONE WARNING `[CATEGORY-GATE] budget read fail-open type=<Name>` (fail-open, L7).

Increment (`record_refusal_async(subject)`): subject None -> no-op; else ONE `llm_spend_breaker._eval(redis_client, REFUSAL_INCR_SCRIPT, [key], [str(expireat)])` through the same dispatch, `expireat = int(next_reset.timestamp()) + 3600` (S81-04 / S81-09 KEY_GRACE_SECONDS); any error -> ONE WARNING `[CATEGORY-GATE] budget record failed type=<Name>`, never raises. Script (module constant, pinned as a literal):
```
local n = redis.call('INCR', KEYS[1])
redis.call('EXPIREAT', KEYS[1], ARGV[1])
return n
```
Atomic: a key can never exist without its EXPIREAT (an INCR-then-EXPIREAT pair of calls could leave a key with no TTL and lock a device out forever). No Lua runtime exists on the box: the fakes emulate the script in Python and a static row parses its text (R-S09-10 precedent).

Budget semantics: the check runs before EVERY consume under the flag (rules 2 and 3), the increment at EVERY post-consume refusal (post-resolve, and the camera's post-vision rule 1); a rule-1 $0 refusal neither reads nor increments. Reason: rule 2 is client-controlled text (prepending "perfume" to any query makes it a rule-2 request), so a budget that skipped rule-2 requests would leave PLAN_S81 :198's unbounded refunded-parse loop open; with the check on every consume the worst case per subject per day is `REFUSAL_DAILY_BUDGET` parse / classify calls (Q-E). Past the budget a device can still get $0 rule-1 refusals but cannot start any compare until the reset (L13).
