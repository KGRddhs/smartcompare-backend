## Findings
### MAJOR
- F1 (app/services/auth_throttle.py `_run`, durable=True: the shielded LOGIN_FAIL / LOGIN_CLEAR writes). On CPython 3.12 (production runtime.txt python-3.12.9; measured on the venv's 3.12) `asyncio.shield` removes its inner done-callback when the outer future is cancelled (`_outer_done_callback`), so when `wait_for` times out (or the request is cancelled) and the pool job LATER raises, nothing retrieves the inner future's exception, and the loop logs at ERROR `Future exception was never retrieved / future: <Future finished exception=<Type>('<message>')>` with the full traceback. Probe: a record write whose EVAL waits past a 0.05 s timeout and then raises ConnectionError('late ...') -> two such ERROR records carrying the exception message (test_sp_durable_timeout_then_raise_no_leak). Production reach (flag ON): any Upstash latency incident where calls exceed AUTH_THROTTLE_REDIS_TIMEOUT_SECONDS (0.5 s) and then fail (httpx ReadTimeout / ConnectError, or an UpstashError with the server's error text) gives ONE ERROR log line + one Sentry error event (LoggingIntegration at ERROR) per login failure and per login success, outside the 60 s per-endpoint memo (R-S24-21) and outside the 'type name only / constants only' rule (R-S24-8); it contradicts the CLAUDE.md row and the PR body, which state that fail-open emits only the memoised `[AUTH_THROTTLE] skipped` WARNING. The texts reachable from upstash-redis 1.7.0 / httpx carry no email or digest (and sentry_service sets include_local_variables=False), so this is a log-contract and alert-noise defect on the fail-open path, not a PII leak. The gate read (not shielded) is not affected. Fix (measured on a byte copy: 199 RED + 37 probes green): in `_run`, right after `job = asyncio.wrap_future(...)`, add `if durable: job.add_done_callback(lambda f: f.cancelled() or f.exception())`; pin it with a row in the new tests/test_s81_s24_gate_rows.py (the probe's form: a late raise after a timeout leaves no asyncio 'never retrieved' record). The same latent form exists in the merged S81-04 `llm_spend_breaker._run_bounded_async(durable=True)` (flag OFF): a follow-up for the orchestrator, not this unit's edit.
