## The four blockers

### R-S07-13 (B1, C1) THE STOP SIGNAL IS NOT AN `Exception`
(a) Every stop the dispatcher or the stage machinery raises (budget, unit ceiling, max_calls, max_minutes, three consecutive transients, the 429 give-up, 401 / 403, a refused host) is ONE class `StageStop(BaseException)` carrying a closed `reason` code and an exit code, never a message built from request or response text. No `except Exception` in the app or the SDK can swallow it; it is caught ONLY by the stage runner. (b) `main` ends with a last-resort handler for any other BaseException except KeyboardInterrupt and SystemExit: the type-only stderr line, exit 3, no traceback. (c) STAGE M: when a stop is raised inside a case, that case and every later case are recorded `not_run` (never `unavailable`, never fail-closed); `not_run` cases are excluded from every rate and counted in results.json; the report prints `n_run / n_total` beside every moderation figure. (d) ROWS: stage-M variants of the auth stop (a 401 at case k: exactly one create for that case, zero creates after it, exit 5, cases k.. recorded not_run) and of the budget stop (no case recorded unavailable; exit 6); the existing R17 / R22 / R23 / R24 keep their stage-A form. (e) Concurrency (R-S07-17): the phase gather uses `return_exceptions=True`; on a StageStop in any task the pending tasks are cancelled and awaited, so no "Task exception was never retrieved" record reaches stderr.

### R-S07-14 (B2, C2-C5) THE CEILING IS HARD
(a) RESERVATION. One budget object per run. A send is admitted only by `reserve(worst_usd)`, which succeeds iff `spent + reserved + worst_usd <= min(stage cap, 15.00 - unit_spent_on_disk)`; the check and the reservation happen with no await between them; the reservation is settled (released, the booked amount added) when the call ends on ANY path. Concurrent sends are allowed only with a reservation each. Row: four concurrent fakes and a cap that fits three worst cases -> exactly three creates.
(b) WHAT IS BOOKED. A priced response books its usage (llm_pricing). An unpriced usage books `worst_usd`. A response with a 4xx status (the request was rejected: 400, 401, 403, 404, 413, 422, 429) books 0.0. EVERYTHING ELSE books `worst_usd`: a 5xx or 529, a client-side timeout, any connection error, a cut or failed stream, any other exception raised after the send began. An error raised BEFORE the send (a local shape error) books 0.0. Over-booking is accepted; under-booking is not. (The 4xx rule is the only billing assumption; it is stated in the report.)
(c) THE INTENT LINE. Before each send the ledger gets a line `{call_id, attempt, state: "sent", worst_usd, kind, stage, setting, site, ts}`, appended, flushed and fsynced; the result line carries the same `call_id` and `attempt` with `state: "done"`. At start the ledger is read back: an intent with no matching done line is booked at its `worst_usd` (a kill, a power loss, a cancelled in-flight call) and its call may be re-sent as a new attempt; every re-send is its own pair of lines and its own booking. A line that does not parse, lacks a required name or carries a non-finite or negative amount REFUSES the start (exit 2, the file name and the line number only).
(d) STREAMS. The usage of a stream = the usage of the `message_start` event updated field by field by every later `message_delta` usage (the field names measured on the pinned SDK). A stream that ends without its stop event, or raises, books `worst_usd`. R38 asserts the booked amount.
(e) ONE RUN PER FOLDER. `<out>/.meas_lock` is created exclusively at start and removed at exit; a present lock refuses the start (exit 2) naming the path, so two processes can never share one ledger. The message says the lock is removed by hand only after confirming that no run is live.
(f) THE LONG-CONTEXT ROW. The worst case uses the long-context price whenever the input BOUND passes the tier threshold (the bound, not the later count).
(g) STAGE W ONLY: the injected search results are bounded by a constant, not counted (L8 stays a stated limit and the report says that the workspace spend limit is the backstop for that stage).
(h) Mutants: reservation removed; a timeout booking 0; the intent line written after the send; the lock skipped; the long-context row ignored in the bound. Each killed by a named row.
