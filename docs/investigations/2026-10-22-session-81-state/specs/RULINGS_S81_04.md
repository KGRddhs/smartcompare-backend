## Design rulings
- R-S04-1 (Q1, refuted claim 11, contract risk 4): "one atomic Upstash operation each" is read as AT MOST one. Each lane total is memoised per process (knob LLM_SPEND_MEMO_SECONDS, default 5.0, defensive parse) together with this process's own recorded deltas since the memo; admit reads Upstash only when the memo is stale. record adds its delta to the memo at once and issues the Lua EVAL without awaiting it (durable, shielded). The W1-3 breaker memo is the precedent.
- R-S04-2 (B1, refuted claims 1-2): every breaker Redis call is wall-bounded with asyncio.wait_for under LLM_SPEND_REDIS_TIMEOUT_SECONDS (default 0.5 s: the measured TLS GET is 163-203 ms; defensive parse, per call); a timeout is fail-open (admit, not recorded) with the rate-limited WARNING naming TimeoutError. The calls run on a DEDICATED small pool (`llm-spend`, 4 workers, lazily built, the redis_offloop pattern), never the qaren-worker default pool and not the redis-offloop pool (it queues behind catalog GETs). `_client() is None` short-circuits on the loop before any hop (the test tier). The record EVAL runs on the same pool.
- R-S04-3 (B2, refuted claim 4, spec Q5, question 3): an unpriced actual records the ADMITTED upper bound when one exists, else a conservative per-provider fallback at the recorded tokens (Anthropic: the Sonnet 5.5 rates; OpenAI: the gpt-4o rates; any other provider: the Sonnet rates), never zero. The admit side of an unpriced model uses the same conservative bound (not a bare WARNING). Stated in the 2.8 contract for S81-06 / S81-16 / S81-21 / S81-22.
- R-S04-4 (Q3, correction 1, refuted claim 5): the compare-entry check refuses when spent + LLM_SPEND_ENTRY_RESERVE_USD (knob, default 0.10, defensive parse) >= cap, at the same place as the W1-3 preflight (inside compare_from_text and the stream, before any provider work), so the refusal travels through the existing LLM_UNAVAILABLE non-delivery with its refund (R-A3).
