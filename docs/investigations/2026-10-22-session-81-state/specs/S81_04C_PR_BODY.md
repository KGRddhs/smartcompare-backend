### What it does
An `api_budget_service.LLMUnavailableError` (or any subclass) that reaches one of the eight request-path except arms now logs ONE WARNING by type (`<prefix>: <TypeName>`, no `exc_info`, no exception text) in every flag state. On sentry-sdk 2.68.1 with `LoggingIntegration(level=logging.ERROR)` a WARNING is neither an event nor a breadcrumb, so the ARM'S LOG RECORD of an exhausted spend lane, an open W1-3 breaker or a vision-V2 no-content outcome no longer raises one Sentry event per refused request. With a role flag ON, an Anthropic SDK error that the router turns into a class member (`AnthropicDispatchError`) is still captured once by the explicit `AnthropicIntegration` (measured by the observability adversary: 1 event, mechanism `anthropic`); that is pre-existing, unchanged by this unit, and not reachable in production while the role flags are unset. There is no flag: nothing else moves.
