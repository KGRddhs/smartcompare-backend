# S81-08b LEGACY-FINGERPRINT-READER unit brief (orchestrator Fable 5.1, 2026-10-24 ~16:20 AST; lane B backend, additive; worktree sc-s81-s08b detached at ea3aef15; dark flag ENABLE_LEGACY_FINGERPRINT_READER, default OFF, read per call; the owner added the unit to the pre-pause list on 2026-10-24: full chain to merge)

What: the backend half of the device-identifier transition that S81-08 CLIENT-FIRST-OTA makes on the client (RULINGS_S81_08 R-S08-4 and R-S08-7). After the OTA the client's `X-Device-Fingerprint` carries the NEW stable id hash (the SecureStore `device_fp_nonce`; IDFV / AndroidId only when SecureStore throws), and at exactly three sites (POST /api/v1/auth/register, the Google and Apple social sign-ins, and the share / invite path) it ALSO sends `X-Device-Fingerprint-Legacy` = today's composition (the SHA-256 over device properties including osBuildId; 64 hex) until the client's runtime cutoff 2027-03-31T21:00:00Z. Every stored-row match the backend makes against `users.device_fingerprint_hash` (migration 021) was recorded from the LEGACY composition, so without this unit every existing device looks NEW after the OTA: the anti-farming re-signup inheritance of the free counters, the referral SAME_DEVICE check (`abuse_detection_service.evaluate_invite`) and the social-login fingerprint apply (W3-3, `ENABLE_SOCIAL_DEVICE_FINGERPRINT`) stop matching. This unit makes each of those matches accept the NEW value OR the LEGACY value when the legacy header is present and valid, stores the NEW value on the rows it writes, and must be LIVE (merged, deployed, flag ON) before the first post-approval OTA (the DEFECT_LEDGER S81-08b row is the OTA precondition). Build 3 never sends the legacy header, so with the header absent the ON path must equal the OFF path byte for byte: that is the OTA-safety argument, and it is pinned, not assumed.
