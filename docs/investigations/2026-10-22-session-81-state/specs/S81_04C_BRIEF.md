## 0 What the unit does

An `LLMUnavailableError` (app/services/api_budget_service.py:706) is the typed "no dispatch / no content" outcome of the LLM chokepoint. With every role flag OFF (production today) the request-path arms that catch it log an ERROR record, two of them with `exc_info=True` and the exception text: one Sentry event per refused request (sentry_service.init_sentry: `LoggingIntegration(level=logging.ERROR)`, the default event level). Once a spend lane is exhausted, or a breaker is open, that is a storm of identical events exactly when the breaker is doing its job. S81-04c makes those arms log the class at WARNING by type in every flag state, and changes nothing else. It is recommended before the owner's ENABLE_LLM_SPEND_BREAKER canary.

The four arms R-S04-10 names (role flags OFF line / the S81-06 role-ON line already at WARNING by type):
- extraction_service.parse_product_query: `:1576` `logger.error(f"Product parsing error: {e}", exc_info=True)` / `:1573-1574`; then the parse-error dict.
- extraction_service.generate_comparison: `:2819` `logger.error(f"Comparison generation error: {e}", exc_info=True)` / `:2816-2818` (WARNING + re-raise, R-S06-2); then the base error dict.
- image_routes camera vision arm (non-delivery exit 1 of 6): `:396` `logger.error(f"[IMAGE] Vision call failed: {e}")` / `:393-394`; then both refunds and the 503 / 500 mapping at `:408-413`.
- url_extraction_service AI extraction: `:993` `logger.error("AI extraction error: %s", type(e).__name__)` / `:988-990` (WARNING + re-raise, R-S06-3); then `{"error": str(e)}`.

## 1 THE RULING: option (1), the class-wide downgrade (R-04C-1)

Option (1) of the G11 brief is ruled: at every arm in scope an `LLMUnavailableError` (and every subclass) logs ONE WARNING by type, `"<the arm's existing prefix>: %s", type(e).__name__`, with no `exc_info` and no exception text, whether or not a role flag is ON. Option (2), a spend-only cut, is rejected. Reasons:

1. It is the unit as two FOCUS chains defined it. R-S04-10: "downgrading them for LLMUnavailableError is follow-up S81-04c". R-S06-12: "dispatch-level refusals log at WARNING by type (never exc_info ERROR: the S81-04c class, folded here for the four sites named)". The comments at the arms name "the S81-04c class". S81-06, a flagged unit, could not change the flags-OFF line, so it pinned it (G03c) as ITS flag-OFF identity; the unit that owns the change re-pins that row as a deliberate E-row (house procedure 4.1).
2. One rule in every flag state. The pivot's target state is role flags ON, where the class already logs at WARNING by type. Option (2) would leave three behaviours (a spend refusal WARNING; other class members ERROR with role flags OFF; WARNING with a role flag ON) and add a predicate or a subclass contract to the breaker that a later class-wide change would supersede (doubt 3 of the G11 brief).
3. Every raiser of the class is a deliberate, typed outcome, and the ones measured log their own line first: the spend refusals log `[SPEND] ... dispatch refused` / `reservation refused` at WARNING (llm_spend_breaker.py:1043 / :1223), the vision-V2 no-content raise logs `[VISION_V2] no content: finish_reason=... refused=...` at WARNING (openai_service.py:503-508). The arm's ERROR is therefore a duplicate, per request, of an outcome already on the log. (The W1-3 denial at api_budget_service.py:1009: the spec measures whether `_openai_dispatch_admission` or the breaker state change logs; see Q2.)
4. The alerting doubt (Q2 of the G11 brief) is closed for today by reachability, not by the Sentry rules: the class cannot reach any arm in production while ENABLE_LLM_PREFLIGHT_BREAKER, ENABLE_VISION_IDENTITY_V2, ENABLE_LLM_SPEND_BREAKER and every role flag are unset on web (the dated values read, ledger line 316 of 2026-11-07 06:22, plus the flips filed since: item 32 only; re-checked by the orchestrator at this brief), so no event of the class exists today for a rule to key on, and every NON-class exception keeps its ERROR record byte-identical (R-04C-5). For a later flip of one of those flags the flag's own CLAUDE.md row states the level (R-04C-9).
5. Hygiene: the two f-string lines print the exception text; the WARNING-by-type form carries a constant and a type name only (the house log rule).
