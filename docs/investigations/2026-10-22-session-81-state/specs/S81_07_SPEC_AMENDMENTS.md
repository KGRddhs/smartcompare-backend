## R-S07-13 THE STOP SIGNAL (replaces spec 2.5 (b) "stop with", 2.8 stage-M failure text, 2.12 last sentence, 2.14 rows 4-8)
- `class StageStop(BaseException)`: `__init__(self, reason, exit_code)`; attributes `reason` (a member of `STOP_REASONS`) and `exit_code` (int). Its `str()` is the reason code only; it never carries request or response text.
- `STOP_REASONS = ("budget", "unit_ceiling", "max_calls", "max_minutes", "transient", "rate_limit", "auth", "host_refused")`. Exit codes: `auth` -> `EXIT_AUTH` (5); `unit_ceiling` -> `EXIT_UNIT_CEILING` (4); every other reason -> `EXIT_STOPPED` (6). (`rate_limit` stops the SETTING only, never the stage: the dispatcher raises it, the setting loop catches it, records `stop_reason` "rate_limit" for that setting and the next setting runs; the stage exit is then 0 unless another stop follows.)
- StageStop is caught ONLY by the stage runner (one `except StageStop` arm in the stage runner of `main`); no `except Exception` in the harness wraps a dispatcher call in a way that could catch it (it cannot: it is not an Exception).
- `main` ends with a last-resort arm: `except KeyboardInterrupt` -> flush, the PARTIAL report, exit 130; `except SystemExit: raise`; `except BaseException as exc` (any other) -> ONE stderr line exactly `meas_claude_gate: crashed class=<type(exc).__name__>\n`, a crash record `{"crash": "<Type>"}` in results.json when `--out` is writable, exit 3, no traceback (the exception object is never formatted, never `str()`-ed, never `repr()`-ed).
- STAGE M: a StageStop raised inside case k marks case k and every later case `not_run`; a `not_run` case is excluded from every rate; results.json carries `n_run` and `n_total`; REPORT.md prints `n_run / n_total` beside every moderation figure; a stopped case is never `unavailable` and never fail-closed.
- Concurrency (A1 phases): `asyncio.gather(*tasks, return_exceptions=True)`; on a StageStop in any task the pending tasks are cancelled and awaited before the StageStop is re-raised; no "Task exception was never retrieved" record reaches stderr.

## R-S07-14 THE CEILING IS HARD (replaces spec 2.5 (a)-(e), 2.7, 2.14 row 5)
(a) THE BUDGET OBJECT (CHOICE). `Budget(stage_cap_usd, stage_spent_usd, unit_spent_usd)`: `stage_spent_usd` = this stage's booked total read back from disk at start, `unit_spent_usd` = the booked total of EVERY `<out>/*/spend.jsonl` read back at start (this stage's included). Attributes `spent` (this stage, start + this run), `unit_spent` (start + this run), `reserved`. `reserve(worst_usd) -> bool` is SYNCHRONOUS (no await inside, so check and reservation are atomic on the loop): True iff `spent + reserved + worst_usd <= stage_cap_usd` AND `unit_spent + reserved + worst_usd <= UNIT_CEILING_USD`; on True `reserved += worst_usd`. `settle(worst_usd, booked_usd)`: `reserved -= worst_usd`, `spent += booked_usd`, `unit_spent += booked_usd`. `Dispatcher.send` calls `reserve` before the intent line and `settle` in a `finally` on EVERY path. A failed `reserve` raises `StageStop("budget", 6)`; when the unit term is the one that fails the reason is still `budget` (the unit ceiling refusal at START is `unit_ceiling`, exit 4, spec 2.3 step 9).
(b) WHAT IS BOOKED (`booked_usd_for_exception(exc, worst_usd, sent)`): `sent False` -> 0.0; an `anthropic.APIStatusError` whose `status_code` is in `UNBILLED_STATUSES = (400, 401, 403, 404, 413, 422, 429)` -> 0.0; EVERYTHING ELSE -> `worst_usd` (a 5xx incl. 502 / 503 / 504 (measured: InternalServerError), 529 OverloadedError, 409 ConflictError (not ruled unbilled: over-booking accepted), `APITimeoutError`, `APIConnectionError`, a cut or failed stream, any other exception after the send began). A priced response books `usd_from_usage(model, usage, worst_usd)` = `llm_pricing.anthropic_usage_record(model, usage, ...)["cost_usd"]` (equal to `llm_pricing.price_call` of the usage fields, cache reads and web searches included); an unpriced usage (None) books `worst_usd`. The report states the 4xx rule as the only billing assumption (results.json `billing_assumption` = the fixed string `4xx rejected requests are not billed`).
(c) THE INTENT LINE. Before each send: `{call_id, attempt, state: "sent", worst_usd, kind, stage, setting, site, ts}` (closed key set `LEDGER_INTENT_KEYS`), appended, flushed and `_fsync`ed; then the send; then the done line (closed key set `LEDGER_DONE_KEYS` = `call_id, attempt, state ("done"), stage, setting, site, case_id, rep, model, kind, ok, usd, worst_usd, input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, web_search_requests, stop_reason, error_class, status, latency_ms, ttft_ms, ts`), appended, flushed and `_fsync`ed. The spec's `retry` key is DEAD: `attempt` (1-based, per call_id, counted across runs and across 429 re-sends) replaces it. Two `_fsync` calls per send. At start every ledger is read back: an intent with no done line of the same `(call_id, attempt)` is booked at its `worst_usd`; its call is NOT completed and is re-sent as attempt + 1. A call_id is COMPLETED when it has a done line with `ok` true or with a non-transient `error_class` (BadRequestError, AuthenticationError, PermissionDeniedError, NotFoundError, RequestTooLargeError, UnprocessableEntityError, ConflictError, AnthropicShapeError); a re-run never re-sends a completed call_id. A line that does not parse as a JSON object, lacks a key of its closed set, or carries a non-finite or negative `usd` / `worst_usd` REFUSES the start: exit 2, one stderr line `meas_claude_gate: refused: ledger_corrupt file=<path> line=<n>` (the path and the 1-based line number only, never the line's content).
(d) STREAMS. `stream_usage(events) -> (usage_dict, complete)`: `usage_dict` starts from the `message_start` event's `message.usage` (class `Usage`) and is updated FIELD BY FIELD by every later `message_delta` event's `usage` (class `MessageDeltaUsage`, fields measured: cache_creation_input_tokens, cache_read_input_tokens, input_tokens, output_tokens (the only required field), output_tokens_details, server_tool_use); a field whose delta value is None does not overwrite. `complete` is True iff a `message_stop` event was seen. MEASURED: a stream truncated after `content_block_delta` ENDS ITERATION WITHOUT RAISING on the pinned SDK, so the harness itself must check `complete`; an incomplete or raising stream books `worst_usd`. The done line of a stream carries `kind "stream"`, the booked usd and `ttft_ms` = the time of the first `content_block_delta`.
(e) ONE RUN PER FOLDER. `<out>/.meas_lock` (`LOCK_NAME`) is created with `os.open(..., O_CREAT | O_EXCL | O_WRONLY)` at start (after the env scan and the key check, before any other write; every stage, `--dry-run` and `report` included) and removed in `main`'s `finally`. ## A9. The canary alphabet (DEVIATION from R-S07-18 (a), stated)
`secrets.token_hex(16)` is generated at run time as ruled, then each hex digit is mapped to the letters G..V (`str.maketrans("0123456789abcdef", "GHIJKLMNOPQRSTUV")`) before use. Reason: with a raw hex body the ruled 4-character window collides with the 16-hex `call_id` values and raw file names the harness legitimately writes (each 4-hex window has a 1 / 65,536 chance per position, and a run writes hundreds of hex ids), so a correct harness would fail at random. The mapped body keeps the run-time randomness and the 4-character window while removing the false positives. The canary is not a credential shape.
