## MAJOR

### A1. The payload future is cancelled by the job's own bound; the later set_result crashes the product fetch
Where: spec 2 (a) "fut gets unified_search after SCS:6232", (c) "IMAGE_LATE_MAX_SECONDS", the late cascade "await fut".
Evidence: the job is `_late_image_job(coro, image_late_max_seconds())`, a wait_for around the cascade; the cascade awaits the bare future `fut` after Serper misses. When the bound fires, the task awaiting `fut` is cancelled and asyncio cancels the future it waits on (Task.cancel cancels its _fut_waiter). The unified search that sets `fut` runs at SCS:6229 inside the try that ends at the `except BaseException:` orphan arm (SCS:6346); a `fut.set_result(...)` on a cancelled future raises InvalidStateError there, the orphan arm cancels the price and specs tasks and re-raises (SCS:6346-6362), so the product fetch fails and the compare degrades to a partial or INSUFFICIENT_DATA. Reachable whenever cache GETs + the unified search outlast the bound: the search is bounded only under ENABLE_UNIFIED_SEARCH_BOUND (12 s, SCS:6205-6227) plus the loop lag, and the knob accepts any positive value (an ops value under 12 s makes it common). The spec guards only the orphan arm ("if unset").
Fix: the cascade awaits `asyncio.shield(fut)` (or asyncio.wait on it) so its cancel never cancels `fut`; both set sites use `if not fut.done(): fut.set_result(...)`; clamp IMAGE_LATE_MAX_SECONDS to at least the unified-search bound plus margin (or state it). Add a RED row: bound 0.2 s, unified search fake 0.5 s, Serper misses: the compare returns success with both products' specs and price, no InvalidStateError, `[IMG_LATE] late_bind outcome=no_picture` (a mutant without the guard must fail it).

### A2. The partial drain skips the page-image chain: ON shows FEWER pictures than OFF on every post-Phase-1 partial
Where: spec 2 DRAIN, (b) "the override part of SCS:6469-6505 is skipped ON and runs at the bind", row 9, E13.
Evidence: OFF writes the page image into result['image_url'] inline at Phase 1 end (SCS:6465-6505), so a partial built later (sync post_gather / scoring / verdict stage via _partial_product_data, SCS:4626, 3851; the stream tail via _emit_stream_deadline_partial, SCS:5082-5090) carries it. ON leaves result['image_url'] = None when the job is still pending and defers the override to the bind, which a hard cap or a tail deadline never reaches; the drain as specified binds only DONE job results. So a product with a valid page image and a pending (or picture-less) job shows a picture OFF and a placeholder ON. This breaks the spec's own promise "ON never shows fewer pictures than OFF" (row 11).
Fix: the drain runs the SAME synchronous chain as the bind on the current (possibly post-swap) price: override via row 10 (hit), else the done job result, else the Phase-1 page image (fallback); outcomes partial_attached / partial_missed keep their meaning. Add a parity row: page image present, job pending, cap during the verdict: the sync and stream partials carry the page image ON and OFF (PIN-green at base, RED against a drain-without-chain mutant).

### A3. The cache name drops the concentration: with the resolver ON one entry serves EDT, EDP and Parfum for 7 days
Where: spec 2 (c) "Name: imgpick:v1: + sha256 over category|brand|line|axis", E19, M9.
Evidence: relevance_kwargs carries brand, line (= product_info name), category and slot only (image_relevance.py:592-608). With ENABLE_PRODUCT_RESOLVER ON, apply_resolution writes name = the line and puts the concentration and size into variant (product_resolver.py:1321-1326: `product["name"] = side.line`, `product["variant"] = " ".join(p for p in (concentration, size) if p)`). The Serper query, however, is the FULL name (RelevanceCall.query -> image_query(product_name), image_relevance.py:566-570, 630-631; scs passes full_name). So a Dior Sauvage EDT pick is stored under (fragrances, dior, sauvage, s1) and served for Sauvage EDP and Sauvage Parfum (visibly different bottles) for 604800 s, with no [IMG_RELEVANCE] line. The investigation asked for "a key that includes brand + line + size" (T2_pictures.md row T2-05). With R OFF the typed line already carries everything, so the defect lands exactly when the resolver is flipped (mix rows 4 and 5).
Fix: add a fourth identity part: the folded variant with size and unit tokens removed (the guard's own SIZE_TOKEN / UNIT_WORDS rules), i.e. the concentration; or name the entry from the folded image query minus size tokens. E19 gains: (Dior, Sauvage, EDT) != (Dior, Sauvage, EDP); (Dior, Sauvage, EDP 100ml) == (Dior, Sauvage, EDP 50ml); and equal across slot 0 / slot 1 (a mutant hashing the slot must die).

### A4. A cached pick bypasses every later guard change, and the read check is weaker than the guard
Where: spec 2 (c) "read check: u passes _is_valid_image_url (D03 deny included) and is https", the v1 prefix, Q6.
Evidence: a cache hit returns at once and builds no RelevanceCall (spec (c)), so nothing re-tests the picture for up to 7 days. (1) The guard's deny is flag-free (image_relevance.py:333-340 uses deny_hosts.is_denied_url / is_denied_source "in every ENABLE_DATA_GUARDS_V2 state", docstring lines 8-11), but _is_valid_image_url denies only when data_guards_v2_enabled() reads ON (image_service.py:66-69): a URL on a host added to the deny list after the write is served while DATA_GUARDS_V2 is OFF. (2) INC-I2b (named in the spec as the next unit) changes the guard words; entries accepted under the old words keep being served, and the key carries no guard version, only the short-line axis.
Fix: on read, apply the guard's flag-free deny (deny_hosts.is_denied_url) plus https in addition to _is_valid_image_url, and require the value to be a dict (get_cached returns any JSON, cache_service.py:641-649). Put a guard-rules version in the name (a constant beside FLAG_ENV in image_relevance, e.g. part of the prefix) and pin it: a RED-file row records the sha256 of the source of check, _check_short_line, identity, RelevanceCall.accept / accept_pick / organic_passes at base together with the version, so any later edit of the guard fails the pin until the version (hence the prefix) moves; state the rule in the CLAUDE.md block. Rows: a cached URL on a denied host with DATA_GUARDS_V2 OFF is a miss (`cache=miss`, the cascade runs); a cached http URL is a miss; a non-dict value is a miss.

## MINOR

### B1. The bind waits for the job even when the post-swap page image will win
Where: spec 2 BIND. Evidence: the bind applies (1) the post-swap page override first; when it hits, the cascade result is discarded, yet the single asyncio.wait still holds the tail up to IMAGE_LATE_BIND_MAX_WAIT_SECONDS for that product (the genuine-BH page-image case is the common one, SCS:6465-6505). Fix: evaluate the override first; wait only on products whose override misses; log `waited_ms=0` for the others. Also guard the empty set: asyncio.wait raises ValueError on an empty iterable, and the OFF path must return before any await (no new suspension point in the stream generator).

### B2. elapsed_seconds misses the bind wait
Where: spec 2 BIND "immediately before t_build (sync SCS:4838, stream SCS:5743)". Evidence: `elapsed = (datetime.now() - start_time).total_seconds()` is computed just above t_build at both sites (SCS:4836, 5741) and fed to build_comparison_response (elapsed_seconds, saved to History), while orchestrator_timings total_ms is computed after the build. Fix: put the bind immediately before the `elapsed =` line (still after the verdict, scoring, badges and confidence, none of which read image_url: scoring_service / trust_validation_service hold no image_url reader).

### B3. The new [IMG_TIER] line breaks the closed X2a grammar, and the late cascade adds cancel points the cancel grammar does not name
Where: spec 2 (g). Evidence: tests/test_inc_x2a_image_tier_timing.py:32-36 defines the closed grammar `tier=(piggyback|search_payload|serper_budget|serper_images|llm_pick) outcome=(hit|miss|skipped|error:...) ms=N` and the cancel grammar `cancelled tier=(serper_images|llm_pick)`. `[IMG_TIER] tier=page_override outcome=fallback product=0` matches neither (new tier, new outcome, no ms). The late cascade adds awaits the base never had (the cache read job, the credit job, `await fut`), so its "base cancel grammar" line can name a tier outside the cancel set. Fix: emit the override as `[IMG_LATE] page_override outcome=<hit|fallback|skipped> product=<0|1>` (or formally widen the grammar in X2a, CLAUDE.md and the canary in one place), and define the in-flight name at each new await (e.g. cache, serper_budget, search_payload) with E11 cancelling the job at each of them.
