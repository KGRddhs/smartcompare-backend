## What the flag does

`ENABLE_USAGE_PATH_OFFLOOP` is a NEW name (unset in production by construction), one reader `app/utils/redis_offloop.py::usage_path_offloop_enabled` (the leaf-module idiom `os.getenv(NAME, "").strip().lower() in ("true", "1", "yes", "on")`), read PER CALL as the FIRST statement of `usage_service.get_usage_status` and `check_usage_allowed`, and once per `review_service.get_reviews` call into a local (one call never mixes states).

- `app/utils/redis_offloop.py`: `usage_path_offloop_enabled()` and `run_redis_offloop_pool(fn, *args, durable=False)` (one job on the SHARED `redis-offloop` pool whatever `ENABLE_PRICE_PATH_REDIS_OFFLOOP` says: copied contextvars, `durable=True` shielded + quietly retrieved (pinned by r39 since fix round 1), a queued read dropped on cancel). `run_redis_offloop` and the S77 reader / pool functions are byte-unchanged (AST digests r25b); stdlib only. No `db_offload.py` change (R-ST1-1; r25c).
- `app/services/usage_service.py`: `_usage_reads_offloop(user_id)` computes the two date keys on the loop, then ONE `asyncio.gather` of two `run_redis_offloop_pool(_get_redis_count, key)` jobs, listed FIRST (fix round 1, F1-8: with `ENABLE_SYNC_DB_OFFLOAD` OFF both GETs are in flight on the pool while the inline Supabase reads run, pinned by r42), and the EXISTING async helpers `_get_user_tier_info` / `_get_active_referral_bonus` (byte-unchanged, through `run_db`, so the Supabase reads leave the loop only under `ENABLE_SYNC_DB_OFFLOAD`: R-ST1-1 / R-ST1-2); it returns `[user_info, bonus, daily_used, monthly_used]`. If building an awaitable raises (a synchronous dispatch failure) the awaitables already built are closed first (GT-6; pinned under the new order by r42b). The two pure compute bodies `_usage_status_body` / `_usage_allowed_body(user_info, bonus, daily_used, monthly_used)` are the base compute, and BOTH flag states call them exactly once per public call (R-ST1-3, GT-4; the OFF lifetime-free path of `check_usage_allowed` reads no counter and passes 0, 0). The fork: `try: reads = await _usage_reads_offloop(uid)` / `except Exception` -> ONE WARNING `[USAGE-OFFLOOP] dispatch failed fn=<fn> type=<Type> -- inline fallback` and the base inline path / `else: return body(*reads)`: the `try` wraps ONLY the dispatch and the gather (fix round 1, F1-3), so a compute-body exception propagates exactly as at base with no WARNING and no second read pass (pinned by r37); a cancel propagates with no fallback.
- `app/services/review_service.py::get_reviews`: the L1 read via `run_redis_offloop_pool(get_cached, ...)` (nocache honoured); the L2 save is scheduled first (GT-1: defence in depth); each post-extraction L1 write (the baseline write and the consult / YouTube re-cache writes), inside the unchanged FY19 / error persist guard (pinned with the flag set inside the row by r36), goes through `_reviews_l1_write_offloop(cache_key, reviews, prev)`: a `copy.deepcopy` snapshot taken on the loop (a snapshot failure logs by type and skips the write, the response unaffected: r41), then a `fire_and_forget` task `reviews.l1_write` in the drain registry `_BACKGROUND_TASKS` (r38) that waits for `prev` INSIDE the task with `asyncio.wait([prev])` (never on the request path: GT-2; a cancelled `prev` does not drop the next write: r40) and submits a durable pool write; a snapshot failure, a dispatch failure or an exception inside the pool write logs `[USAGE-OFFLOOP] reviews L1 write dispatch failed type=<Type>` and is swallowed (r41, r39[reviews_write]). The L2-promotion write stays the inline base call (RO17, r20). Nothing in D03's `clean_review_citations` / `build_retailer_quotes_from_reviews` (the D03 deny checks at review_service.py:181 / :334 are untouched by this unit).

Flag OFF: byte-identical on every response body and stored row (the same calls, order, arguments and threads; no pool built; no new log line), pinned with the full configuration and call / thread recorders (B1 rule). No new response key, no new status, no new error code; `/health` gains nothing (its existing `redis_offloop_pool` key appears once the pool exists, r26). `consume_comparison_credit`, `_refund_credit_sync`, every quota key and the two gathered helpers are AST-digest pinned (r25b, 28 digests).
