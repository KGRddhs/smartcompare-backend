## 2. Refuted claims (measured truth)

RF1. Offer "latest" semantics (2.3 view + 2.3 UNIQUE + 2.3 prune + 9 limit 7). The spec says an identical re-observation BUMPS last_seen on the UNIQUE key while the view and the prune order by captured_at. Measured A/B/A on PG 18.1 (probe045.out P6): a 30.000 row first captured 400 days ago and re-observed today (last_seen today), a 25.000 row captured 200 days ago (last_seen 199 days ago). `kb_offers_latest` returns 25.000; `kb_product_card` offers = [25.000]; `kb_prune_offers(30, 1)` deletes ONE row and it is the CURRENT 30.000 row; the stale 25.000 survives. "The latest offer per merchant is never pruned" (2.3) is false whenever a price returns to an earlier value.

RF2. kb_merchants serves S81-15 "for the CTA label only" (spec header line 9). The S81-15 spec (sc-s81-s15/.qa-s80/S81-15_UNIT_SPEC.md:94, :101, :337) makes `kb_merchants.registry jsonb NOT NULL DEFAULT '[]'` a BINDING addition to 045 (D-1) and reads `host,status,deny,blocked_reason,registry,partner,updated_at`; its Q1 is "blocking for GREEN". Measured why: `noon.com` has two literal rows (source_router.py:308 gcc render-only, :329 bahrain noon_catalog) that the host PK cannot hold, and the Source dataclass (source_router.py:31-90: domain, tier, categories, weight, usage, is_shopify, is_render_only, is_algolia, requires_super, locale_paths, subdomain_patterns, currency, discovery_query_templates, mechanism, pdp_url_pattern, sample_url, status, priority_rank, search) plus the JSON row keys (categories, tier, weight, mechanism, genuine_method, priority_rank, sample_url, search; data/bh_gcc_sources.json, 368 rows) have no 045 column. S81-15 Q6 also assumes `platform_confidence` is a text enum; 045 makes it numeric(4,3).

RF3. kb_variant_key invariant (2.4: `kb_variant_key(kb_product_id(b,n,v), extract_concentration(s), extract_size_ml_any(s)) == spine_key(b,n,v)`). `extract_size_ml_any` returns 0, not None, for "0ml", "00 ml" and "10000 ml" (`_SIZE_ML_RE = (\d{1,4})\s*(?:-?\s*)ml\b`, price_service.py:4066; probe_keys.out). spine_key maps 0 to "-" (spec_spine_service.py:242 `str(ml) if ml else "-"`), while 2.4 / R23 send 0 to None, so the invariant is false for those surfaces.

RF4. 1.3 "extract_size_ml_any: int ml ... None when absent". It also returns 5 for "0.5 ml" and for "Sauvage EDP 7.5ml sample" (the decimal is cut), and 10 for "100ml + 10ml travel spray" (smallest of several), with identity "plus-sauvage" (probe_keys.out). So the SKU axis mis-sizes every decimal mini / sample and gift sets; no stated limit says so.

RF5. 9 limit 2 ("the deny-label regex ... stricter than D03's registrable-label rule: `parfumo.shop.example` is refused"). `deny_hosts.kb_source_allowed` (whole-token rule via `is_denied_source`, deny_hosts.py:198-223) ALREADY refuses `parfumo.shop.example` and `https://fragrantica.com.evil.test/x`, and refuses a path token (`https://shop.example/fragrantica-notes`) the SQL accepts; it ALLOWS `notfragrantica.example`, which the kb_gaps.source_hint CHECK (`!~* '(fragrantica|parfumo|basenotes|fimgs)'`, a bare substring) refuses (probe_deny.out). The two rules differ in both directions; the stated premise is false.

RF6. canonical_offer_url "every non-None output matches the 045 canonical_url CHECK" does not follow from the stated rule "ASCII [a-z0-9.-] with a dot". `urlsplit(...).hostname` yields `shop..example`, `-shop.example`, `shop-.example`, `.shop.example` (probe_keys.out), all of which pass the stated rule and fail the 045 host regex (PG 18.1: kb_merchants_host_check rejects `shop..example` and `-shop.example`, probe045.out P4). `.port` RAISES ValueError for `:abc` and `:99999`; R25's ~20 rows include neither class.

RF7. P2 "no `"kb_` table / rpc literal in app/ or scripts/ outside kb_service.py" is not green at base as literally worded: `app/services/deny_hosts.py:242` carries the string constant `"kb_source_allowed"` in `__all__`.

RF8. kb_product_id refuses only an empty brand axis or identity. It mints `fragrances|unknown|product|-` for ("Unknown", "Unknown Product") (spine_key `fragrances|unknown|product|-|-`), while `result_gate.is_placeholder_identity(dedup_brand_name("Unknown", "Unknown Product"))` is True (probe_placeholder.out).
