## Verdict: BLOCK
Four blocking issues on the two FOCUS surfaces (the spend path and the stop conditions) and on RED satisfiability. Each is fixable by a ruling plus a spec edit; none needs an app/ byte.

## Blocking issues
- B1 STAGE M SWALLOWS EVERY STOP. The harness replaces `llm_router.guarded_anthropic_create` (spec 2.8), but its caller `_moderate_step` (llm_router.py:1164-1181) catches AnthropicRefusalError, LLMUnavailableError, ValueError/TypeError and then `except Exception` -> (None, "unavailable"). Any stop the dispatcher raises as an Exception (budget, max_calls, max_minutes, 401/403, three transients, the 429 give-up) becomes a fail-CLOSED "unavailable" case and the loop moves to the next case: a 401 does NOT stop at once (R-S07-5), every later case is re-attempted, and a budget stop turns every remaining case into a fail-closed result, so results.json reports a fail-closed rate near 1.0 and MODERATION reads NO-GO for the harness's reason, not the model's. Required: the stop signal is a BaseException subclass (not Exception), or a stage-level stop flag checked before each case with the case recorded not_run; R17 / R22 / R23 / R24 gain a stage-M variant.
- B2 THE SPEND CEILING IS NOT HARD (R-S07-4, FOCUS). (a) A1 runs {specs x2, price x2} concurrently (2.6) and 2.5 (b) checks stage_spent + worst_usd with no reservation: every concurrent task passes the check before any books. (b) 2.5 books usd 0.0 on every exception; a client-side timeout (CALL_TIMEOUT_S 25.0) or a connection drop after the request was sent can be billed, and 2.7 re-sends every transient line on resume, so one call can be billed twice and booked 0 twice. (c) The ledger line is written AFTER the response (2.5 (e)): a hard kill, a power loss, or an in-flight concurrent call cancelled by Ctrl-C loses billed spend and resume re-sends it. (d) A2 streams (`create(stream=True)`) have no resp.usage; 2.5 (d) is undefined for kind "stream". Corrections C2-C5.
- B3 verdict_fallback IS NOT CAPTURABLE AS SPECIFIED AND MEASURES NOTHING NEW (RC1). Drop the setting (its request equals verdict's) or rule a capture seam that reproduces the real branch.
- B4 RED IS NOT SATISFIABLE AS WRITTEN (RC7, RC8, RC11): the conftest placeholder OPENAI_API_KEY makes step 3 refuse every R row; R11's static rule forbids the spec's own placeholder store; P06 is a skip at base. Corrections C9-C12.
