## Blocking (close before RED)

- **B1 Bound and isolate every awaited breaker read.** `admit_async` and `entry_refuses_async` must be wall-bounded (`asyncio.wait_for`, a knob such as `LLM_SPEND_REDIS_TIMEOUT_SECONDS`, default about 0.3 s, defensive parse, read per call) with a timeout = fail-open + the rate-limited WARNING naming `TimeoutError`; run on a dedicated small pool (a `llm-spend` ThreadPoolExecutor of about 4 workers built lazily, or the existing `redis_offloop._get_redis_offloop_pool()`), never the `qaren-worker` default; `record_soon` likewise. Short-circuit `_client() is None` on the loop before any hop (makes the test tier truly inert and saves a hop per call when Redis is unconfigured). Add RED rows: a fake whose GET sleeps past the bound -> admit returns admitted within the bound + one fail-open WARNING; the GET thread name does not start with `qaren-worker`; `_client()` None -> zero `to_thread` / executor submissions. Mutants: bound removed; pool swapped back to the default. Rewrite L1 as "fail-open on error and on a read slower than the bound".
- **B2 Make an unpriced call countable.** Leaf API: `record` of an unpriced actual records the admitted upper bound when one exists, else a conservative per-provider fallback (for example the most expensive row of that provider in S81-03's table), never zero; `upper_bound_usd` None on the admit side uses the same conservative fallback (or the orchestrator rules that the brief's "admit with a WARNING" stays and only the record changes). The 2.8 contract item 3 states it for S81-06 / S81-16 / S81-21 / S81-22. RED: an unpriced Anthropic-shaped record writes a positive INCRBYFLOAT; R29 changes accordingly if the rule also covers unpriced OpenAI ids (today it records the 0.00027 mini estimate, an under-count up to 16x for a gpt-4o-class id). ## Contract risks

- One `live` lane for all users is a global availability switch: whoever spends the day's cap (an abuser with several accounts; the device quota S81-09 flips AFTER the breaker in PLAN_S81's flip order) turns every compare into LLM_UNAVAILABLE until 00:00 Riyadh. A per-account / per-device sub-cap or flipping after S81-09 bounds it.
- The public, unauthenticated /health would publish the daily LLM spend and caps, i.e. the remaining budget before that global refusal (question 7).
- Read-admit (no reserve) is weakest exactly where single bounds are large: two parallel offclock batch submits of 1.5 USD each both pass at spent 0 against a 2.00 cap (50 percent overshoot). The 2.8 item 4 contract should require a reserving admit for batch / search submitters (question 5).
- Latency: with the per-call GET the ON state costs about 1 s per compare (1 entry + 4-5 sequential admits at 163-203 ms) against the pivot's "faster compares" goal and the W1-3 precedent of a 60 s memo (abs:694 `_DEFAULT_LLM_BREAKER_CACHE_TTL = 60.0`).
- The refusal shapes are all build-3 renderable (LLM_UNAVAILABLE coded 503 / SSE error / camera 503 / camera comparison_failed outage code); the band deliveries (refuted claim 5) are the only user-visible degradation, and they are charged.
