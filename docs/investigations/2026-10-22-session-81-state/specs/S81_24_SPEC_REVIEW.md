## Blocking (fix in the spec before RED)

B1 The slowapi floor masks V2 in the RED route rows. tests/conftest.py _reset_rate_limiter resets the in-memory limiter once PER TEST only, and the gated routes carry register 3/minute (:688), password_reset 3/minute (:1127), resend 3/minute (:1320), login 5/minute (:800). Rows R20 (register E, E, F, E = 4 requests), R21 (4 registers), R30 (about 7 resets), R31, R10 (16 logins), R13 (20+ logins) and a non-parametrized P70 (3 cases x 6 spellings) exceed the floor in real time (the fake clock moves only _now_ms). Because the V2 429 is byte-equal to the slowapi 429 BY DESIGN (R-S24-7), a slowapi 429 can satisfy a "-> 429" assertion (false pass: the "gate never refuses" mutant survives on R20's second request only if the floor fires, and on R30's 4th request it does) or break a "-> 200" assertion (R20's last request; unsatisfiable). Correction: every V2 route row calls limiter.reset() before EACH request (or patches limiter.enabled False inside the V2 rows only, never in R50 / P74 / P80), and every V2 429 assertion ALSO asserts V2 origin: the fake's EVAL list for that request and exactly one "[AUTH_THROTTLE] throttled endpoint=<e>" record. P70 / P71 are parametrized per (case, spelling).

B2 R60 is internally inconsistent for login. Its text: "one WARNING [AUTH_THROTTLE] skipped endpoint=<e> type=RedisUnconfigured per request". With redis_client None, a login credential failure runs gate (skipped endpoint=login) AND record_login_failure (skipped endpoint=login_fail), and a login success runs gate AND record_login_success (skipped endpoint=login_clear): two lines per login request by 2.5 / 2.7 / 2.9. Correction: R60 states the exact per-route record list (login failure: [login, login_fail]; login success: [login, login_clear]; the other five routes: one line).

B3 MS4: the echo line's "peer" is NOT the TCP peer. The start command (Procfile:1, railway.json deploy.startCommand) runs uvicorn 0.52.4 with no proxy flag, and uvicorn's Config defaults are proxy_headers=True, forwarded_allow_ips=None -> os.environ FORWARDED_ALLOW_IPS else "127.0.0.1" (measured on the pinned venv). uvicorn's ProxyHeadersMiddleware rewrites scope["client"] from X-Forwarded-For whenever the immediate peer is in that trusted set, so request.client.host (the spec's "Peer", 2.8) and slowapi's get_remote_address are POST-rewrite. If FORWARDED_ALLOW_IPS is set on web (names-only state unknown: no ledger line names it), the probe line reads xff_leftmost_is_peer=true on a forged header and an operator would misread it as "the platform overwrites XFF"; L5 ("the per-IP floor keeps keying on the Railway edge peer") is also only true when it is unset. The spec never mentions uvicorn. Correction: 1.7 records the measured uvicorn default and its env name; the [HOP_PROBE] template gains ONE boolean "uvicorn_forwarded_allow_ips_set" (os.environ name presence only, never the value; still counts and booleans only) or the probe step (8.1 b) requires a dated names-only ledger line for FORWARDED_ALLOW_IPS on web first; L5 is reworded conditional on it; R100 / R101 / R103 / R105 and the template pin follow.
