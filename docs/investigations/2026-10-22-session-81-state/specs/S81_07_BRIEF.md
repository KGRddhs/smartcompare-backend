- R-S07-2 STAGES (sub-commands, each with its own cap, ledger and report; the ops lane runs them in this order and may stop after any). A TEXT, the critical path (gates the TEXT / VERDICT / CRITIC flips): for every text site of the router's site table, as the router shapes it (Haiku, thinking disabled, effort low, the site's token cap, `output_config.format` where the site has a schema, no temperature): 20 calls per setting at REAL prompt sizes built by the app's own prompt builders from synthetic fragrance pairs, at the real spacing of one compare, recording time to first token where the site streams, end-to-end time, usage, the cache_read share, stop_reason, refusals, JSON validity and schema acceptance; the Sonnet escalation shape (`between_tools`), 20 calls; the refusal rate on fragrance names incl. - R-S07-3 KEY HANDLING (FOCUS). (a) The key comes from ONE environment variable, read by NAME: `MEAS_ANTHROPIC_TEST_KEY`. (b) The SDK client is built with the key passed EXPLICITLY, and the harness REFUSES to start (a names-only message, a non-zero exit) when `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL` or `ANTHROPIC_CUSTOM_HEADERS` is present in the environment (the production key name, a bearer override or a redirect can never be used by accident), or when the variable is missing or empty. (c) The value never reaches argv, a log line, a report, a ledger row, a repr, an exception message or a traceback: every exception is recorded by TYPE with a scrubbed message; the SDK's own debug logging is off and refused when requested by environment; the pinned SDK's exception text and reprs are MEASURED for a key or header echo, never assumed. (d) Reports carry the variable NAME only: never a prefix, a suffix, a length or a hash of the value. (e) Tests use a fake client only; one row plants a canary value in the variable and proves it appears in NO output byte (stdout, stderr, ledger, results, report, exception text) on the success, SDK-error and crash paths; one row proves no code path reads `ANTHROPIC_API_KEY`.
- R-S07-4 SPEND (FOCUS). A hard ceiling in code: `--max-usd` per stage (proposed defaults A 4.00, M 2.00, V 5.00, W 3.00) and a unit ceiling of 15.00 across every stage ledger in the output folder (a stage that could pass it refuses to start). Every call is priced from its `usage` by `llm_pricing` (the long-context row; a web search priced per search). BEFORE each call its worst case (the counted input at the input price + `max_tokens` at the output price) must fit what is left, else the stage stops. A JSONL spend ledger, appended and flushed per call; a re-run RESUMES and never repeats a completed call. `--max-calls` is the second stop.
- R-S07-5 STOP CONDITIONS: the budget (R-S07-4); any 401 / 403 (stop at once, never retry); three consecutive 5xx / 529 / connection errors; a 429 honoured by `retry-after` at most three times, then the setting stops; a wall-clock bound per stage (`--max-minutes`); an interrupt flushes the ledger and writes the partial report. The SDK's own retries are OFF (the harness owns every retry, so there is no hidden spend).
- R-S07-6 INPUTS: synthetic or owner-written ONLY (PLAN_S81.md:144): public product names and synthetic snippets under the fixtures folder; no production row, no user text, no database, no Redis, no Supabase, no Railway. The only host is api.anthropic.com.
