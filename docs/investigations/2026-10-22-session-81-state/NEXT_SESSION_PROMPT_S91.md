## Lessons of session 90 (binding)
- A log-hygiene unit reaches every raise site of its exception class, not only the unit that named it. `git grep` every raise of the class and its subclasses at the main sha, map each raise to its gating flag, then check that flag against the dated production read. S81-04c's LLMUnavailableError reaches its arms through three production flags (W1-3 ENABLE_LLM_PREFLIGHT_BREAKER, ENABLE_VISION_IDENTITY_V2, ENABLE_LLM_SPEND_BREAKER), so a class-keyed downgrade is not confined to the breaker.
- The production flag state comes from the ledger's dated values read (line 316, 2026-11-07 06:22) plus the flips filed since, never from memory. Reading the Railway variables stays the ops lane's job.
- A brief's measurement needs no worktree. `git -C <clone> show <sha>:<path>` and `git -C <clone> grep -n <pattern> <sha> -- <paths>` read the exact main bytes with no checkout and no CLAUDE.md injection. Grep-filter CLAUDE.md the same way (`git show <sha>:CLAUDE.md` into the scratchpad, then python over the lines you need). S90 measured all of G11 this way at about 31 pct of context.
- A unit that reverses a frozen PIN set on purpose by a FOCUS chain is not SAFE by default. The case here: S81-06's test_g03c_flag_off_parse_site_keeps_the_base_error_line pins the role-flags-OFF exc_info ERROR line for an LLMUnavailableError.
- "Does any alerting key on this log line?" `LoggingIntegration(level=ERROR)` with the SDK's default event level makes every logger.error a Sentry event and a WARNING neither. The Sentry project's alert rules are outside the repo, so the code settles the question only when the line cannot fire at all.
- A test-only dedup that nothing waits on does not merit its own chain. Fold it into the unit that moves the same pins (S81-24c goes into S81-24b).
- Check the DEFECT_LEDGER for every follow-up id a PR body names: S81-24c had no row until S90, and S81-24b / 24d / 24e still have none.
