## Lessons of session 83 (binding)
- A digest / hash constant's NAME must carry none of gitleaks' generic-api-key keywords (access / auth / api / credential / creds / key / password / secret / token): the repo's pre-commit hook runs gitleaks with --ignore-gitleaks-allow and a copy of HEAD:.gitleaks.toml and refuses a .gitleaksignore, so an inline allow or a same-branch config change cannot pass it; the G4 GREEN commit was refused on OPENAPI_PATHS_SHA256 and fixed by the E-row rename SCHEMA_PATHSET_SHA256 (a fix round of its own). Put this check into every RED gate's hygiene list.
- With core.autocrlf=true a FRESH worktree checks LF-only new files out as CRLF: a frozen RED file's on-disk sha in a scratch worktree differs from its blob; compare blobs (`git show HEAD:<path> | sha256sum`) or byte-copy from the lane worktree.
- Reading two ~100 KB specs in one orchestrator window cost ~45 pct of context: file a spec and read it in sections, or delegate a summary, when a third spec lands in the same window; the record (ledger, memory, active_workflows.txt) must always be complete enough to resume after a compaction.
- The merge order of two lanes: whichever is READY_FOR_PR first merges first; the other's final round replays onto the moved main (RULINGS_REBASE_S81_16B is the template: the dry `git merge-tree --write-tree --name-only <other HEAD> <this HEAD>` by the orchestrator first, the union classes named, the base record at the new main by per-file reuse, G9-class gates not re-run when their bytes are unchanged).
