## Lessons of S92-FIX (binding)

- Measure before you accept a report's unit list. Three of the incident report's units changed at the first read: X11 was already built behind an existing flag (a flip, not a unit); X7 could not show on the phone because no client bundle renders the field; X1's stated proof would have made both live bundles compare two different bottles.
- A design that shows new data must be checked against what the LIVE bundles do with every field it touches (they send no app-version signal): putting a value back into a field they already read can create a false claim on today's apps.
- A read-only spec round (git show / git grep, the base pass state deferred to the RED) costs no gate slot; use the waiting time before a slot for specs, measurements and the design work.
- Give read-only agents plain source exports (`git archive <sha> <paths> | tar -x`) and a record copy of the docs: no checkout, no CLAUDE.md injection.
- One alert per state change is not one alert per process: a web process lives from deploy to deploy, so a once-per-process latch mutes the second outage. Rule the transition and a cool-down.
- A liveness check that only proves authentication must never clear a state it cannot observe (quota), and a probe on a metadata endpoint can be refused for a credential that works for the real call: trust only the structured invalid-credential signal from a probe.
- When a unit edits tests/conftest.py its comm set is the whole backend tree: plan the base record once per main sha and share it between units (per-file reuse), and never let two agents run the same base chunks.
- Two RED agents can share one workflow (one slot): the runner's mutex serialises their pytest runs.
- The context goes fast: the read-in cost about a third of the window. Print workflow results through harvest.py with field filters; keep ledger lines in files; let agents write the long documents.
