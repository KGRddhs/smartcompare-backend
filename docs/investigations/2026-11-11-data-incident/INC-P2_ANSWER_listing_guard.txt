For the PR line (the relay's 01:55 question): ENABLE_LISTING_MATCH_GUARD is INC-X10 LISTING-MATCH-GUARD, already merged (CLAUDE.md:645 at 5cd93c6a). It is read first in price_service._vd_gender_line_flip (price_service.py:7828/7837).
- What it changes: for fragrances only, a four-line table (Versace Eros, Versace Dylan Blue, Creed Aventus = men; D&G Light Blue = women) rejects a listing that states exactly one gender other than the line's default, when the query names the line and states no gender.
- Where it acts: the selection axis (every adapter gate, select_best, should_cache_price) and the backstop (the cache read and is_price_showable; that part also needs ENABLE_VARIANT_DESCRIPTOR_AXES). It adds no new key and no log line, and OFF is byte-identical.
- With INC-P2 ON it also carries the Hawas row (P2R-13 / D5).
- Is it safe to open? The failure mode is conservative: a wrong-gender listing goes pending instead of being shown. Known false reject L-X10-7: a pronoun in marketing text ('gift for her' on a men's Eros listing) sends a right listing pending. It fails open for Arabic-only titles (L-X10-6).
- Window owner: INC-X10's own canary window (its owner steps: ENABLE_EXACT_PRICE_GATE and ENABLE_VARIANT_DESCRIPTOR_AXES stay ON). It is not INC-P2's window. For the Hawas fix it must be ON together with ENABLE_PRICE_NOT_LOST: open INC-X10 first, alone, then P2.
