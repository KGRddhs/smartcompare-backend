## 0 What the unit does

Today every text comparison, every camera scan and every link comparison is still DISPATCHED to OpenAI and refused with HTTP 401 (the credential is revoked; no Claude role flag is on). So user content travels to a service that refuses it, which serves no purpose, and the legal text cannot truthfully say "we stopped sending data to OpenAI" (the main lane's path B) while the code sends it. This unit adds one dark flag. With it ON, every call that would go to OpenAI fails LOCALLY, before any network activity, and each user-visible outcome stays what it is today, or becomes the existing coded refusal where today's outcome is a codeless error. With it OFF nothing changes, byte for byte. The day the flag goes ON in production is the date the legal texts would carry.

## 1 THE FLAG RULING (R-12D-1)

A NEW dark flag, proposed name `ENABLE_OPENAI_EGRESS_STOP` (default OFF, read per call with the house idiom as the first statement of its predicate; any value outside true / 1 / yes / on after strip and lower is OFF). The spec may propose a better name; it ships OFF; only the relay sets it, on the owner's yes. Nothing in this unit ships unflagged.

## 2 Scope rulings (binding on the spec; the spec may refine names, never widen)

- R-12D-2 NO BYTE. With the flag ON no code path of this repository, in any production process (the web service, the price warmer, every cron and script service), opens a connection to an OpenAI host or sends a request to one. The local failure happens BEFORE the SDK call is awaited and before any raw HTTP call. The CENSUS decides the set of sites (question Q1), not this list; starting points at the base: the chat chokepoint `guarded_llm_create` (app/services/api_budget_service.py, both branches), the moderation call (app/services/content_safety_service.py, the `moderations.create` line), every site that reaches them through `llm_router.route`, and anything that builds or uses an OpenAI client outside those paths.
- R-12D-3 TODAY'S DELIVERY, PATH BY PATH. With the flag ON each entry (text comparison, its streaming form, camera scan, link comparison, any other entry the census finds) answers what it answers TODAY with the rejected credential: the same status, envelope, copy, credit and refund behaviour, history row and cache behaviour. ONE EXCEPTION, ruled: where today's outcome is a CODELESS error (the camera route's 500 at app/api/image_routes.py with the text "Image analysis failed. Please try again.", the candidate INC-CAM1), the outcome under the flag is the EXISTING coded refusal of that route (the engine-unavailable code and copy, with the refunds that refusal already makes). No new envelope, no new code, no new copy, no client change. The spec measures, for every entry, the outcome for (a) today's authentication error and (b) the typed class LLMUnavailableError raised at the chokepoint, and proposes which exception the local stop raises at each site so that this ruling holds; where neither class gives it, the spec says so and proposes the smallest change.
- R-12D-4 NOT BY OTHER SWITCHES. Never by turning ENABLE_OPENAI_PRE_V3 off, never by removing or blanking the credential variable, never by changing a Claude role flag. The flag is independent of the router's consent decision: a request the router sends to Anthropic is untouched; the stop applies only to what would have been dispatched to OpenAI (every role flag off; the pre-v3 route; moderation while its role is off; the camera while vision is off; any fallback or escalation that lands on OpenAI).
- R-12D-5 NOTHING ELSE MOVES ON A STOPPED CALL: no spend-breaker admit or reservation, no pre-flight breaker admission, probe or failure record (a local stop is not an OpenAI failure and must never trip a breaker), no usage or cost ledger entry, no retry. The spec fixes the order of the stop check relative to those steps and proves it with recorders.
- R-12D-6 A LOCAL STOP IS NOT A CREDENTIAL OUTCOME (the interplay with MON1 of this lane, which is built on another branch and not on the base). This unit must be correct on the base WITHOUT MON1. The spec states, as a contract for MON1's final round, what MON1 must then honour: a stopped dispatch records neither `rejected` nor `ok`; the active check never calls OpenAI while the stop is on; OpenAI is not "in use" while the stop is on (so the monitor path stops being degraded by OpenAI). If MON1 merges first, this unit carries those lines instead; the spec writes both merge orders down.
- R-12D-7 LOGGING: a stopped dispatch never logs at ERROR and never raises a Sentry event. One line with a constant text and the surface name, at most once per process per surface (the spec names it); the arms that catch the raised class log as they do today.
- R-12D-8 MODERATION: with the flag ON the OpenAI moderation call is not made and the existing fail-open outcome of its arm is returned (today the call is made and fails open on the 401). The Claude moderation path is untouched.
- R-12D-9 OUT OF SCOPE: every legal text and processor row (the main lane's S81-12 work); removing the OpenAI SDK or its client code; retiring the credential (window 22); any client change; any change to what a working OpenAI credential would do with the flag OFF; MON1's own files.
