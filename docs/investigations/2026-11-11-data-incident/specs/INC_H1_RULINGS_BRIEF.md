H1-1 SCOPE. Server only: (a) the N/A stamping of specs on the way to the wire; (b) the fact-check rows built from empty values; (c) the reviews no-data answer and its praise; (d) the caching of an all-empty spec sheet and of a no-data reviews dict. H1-2 FLAG. One new dark flag ENABLE_HONEST_EMPTY, read per call with the house idiom, default OFF; flag OFF byte-identical on every entry (pinned).

H1-3 SPECS. Under the flag an empty spec value (None, "", or an NA token: the spec lists the exact set the code already uses, e.g. "N/A", "n/a", "unknown", "not specified", "-") is OMITTED from products[i].specs and from every server spec row, instead of being stamped "N/A"; a field with a real value is unchanged. The spec measures what both live bundles (store JS 683f56c0 and the over-the-air JS on main) render for a product whose specs dict is empty or has only a few keys (the accordion's structural fallback, ResultsAccordion.tsx:199-222 and 293-296, and the "N dimensions" count), and states it: fewer or no rows is the intended interim; the honest empty line is INC-C1's.

H1-4 FACT-CHECK AND THE CHIPS. Under the flag verify_spec_citations skips empty and NA-token values, so empty fields never count as citations: the specs leg cannot be strong from empty fields, and a product with no real spec fields has a reliability total of 0, which the scoring already treats as missing (so no reliability-proxy bar and no "leads on Versatility" built from nothing). The spec walks every flag mix with ENABLE_CONFIDENCE_FACTCHECK_WIRING, ENABLE_RELIABILITY_UNCHECKED_ABSENCE, ENABLE_MISSING_DIM_RENORM and ENABLE_SPECS_NO_FABRICATION (each on and off, as far as their documented activation orders allow) and pins the reachable mixes.

H1-5 REVIEWS. The reviews JSON shape gains "has_review_data" (boolean): the prompt asks the model to set it false when the provided results contain no review evidence for this exact product. Under the flag, when has_review_data is false, or when there are no highlights and the consensus states the absence of review data (a small phrase guard the spec defines: "no review data", "provided search results", "no reliable reviewer consensus", "insufficient review"), the consensus is not used as praise and no review text reaches the wire for that product. The spec measures the prompt digest pins this touches and whether the prompt change must itself sit behind the flag (the house rule: flag OFF byte-identical means the OFF prompt is unchanged).

H1-6 CACHING. Under the flag an all-empty spec sheet (no real field) is not written to L1 or L2, and a reviews dict with has_review_data false (or caught by the phrase guard) is not written to L1 or L2, so a later correct identity is not masked for 7 to 30 days.
