## Goal (one sentence)
A price the server found for the right perfume reaches the phone with its bottle size, and the same pair gives the same prices twice in a row.

## Rulings

- P2-1 FLAG. One new dark flag `ENABLE_PRICE_NOT_LOST` (default OFF, the house idiom, read per call as the first statement of each predicate that uses it). Flag OFF is byte-identical in every response key, status, cache write and log line EXCEPT the three log-only lines of P2-11, which ship unflagged (stated in deploy_visible_delta). No other new flag; knobs only if the spec measures a real need.

- P2-2 PART (a) EACH PRODUCT KEEPS ITS OWN TYPED SIZE (T3-01). Under the flag, on the fragrance reconcile path (PS reconcile_pair_sizes, reached through reconcile_pair_fairness from the sync and stream builds), the pair target is NEVER `min(extract_sizes_ml(user_query))` of the combined "A vs B" text. Each side's typed size is read from that side's OWN typed text only. The orchestrator's measured facts that this ruling must respect: (i) with ENABLE_PRODUCT_RESOLVER ON, PR apply_resolution writes name = the line, search_query = "<brand> <line> <concentration>" (never the size) and puts a typed size into `variant` in compact form ("EDP 100ml"); (ii) with it OFF, the typed size stays inside name / full_name / search_query as typed ("Dior Sauvage 100 ML Edp"); (iii) effective_pair_size_ml reads full_name, name, the price title, price.size and specs volume, NOT variant. So the per-side typed-size reader must give the same answer with the resolver ON and OFF for the same typed input: walk both, with a RED row per mode for "Ted Baker M 30ml" vs "Dior Sauvage 100 ML Edp". Outcomes: both sides typed -> each side is re-selected (from candidates already fetched, no new network) to ITS OWN typed size when a candidate exists, else keeps its found price labelled with its own size (P2-3); never a pend because the two typed sizes differ. One side typed -> that side targets its typed size; the other side follows P2-3.

- P2-3 PART (b) NO EXACT-100 PEND; DIFFERENT SIZES ARE SHOWN, NOT HIDDEN (T3-02; the owner recommendation of 2026-11-15, the owner's flip is his final say). Under the flag, with no typed size: if both sides can reach a COMMON size from their own candidates (the current price plus the retained candidates), keep today's re-selection (prefer 100 ml, the shipped basis, when both reach it; else the largest common size both reach). If they cannot, NEITHER side is pended for size: each side keeps its found showable price, carrying its own size. A side whose size is unknown keeps today's flagship default for this decision (no new pend). Pending for size (reason size_mismatch) no longer happens under the flag on the fragrance path; every other pend (C1 showability, estimates, out of stock, the display check) is unchanged.

- P2-4 NO CHEAPER CLAIM ACROSS UNEQUAL SIZES (comparison-neutral). When the pair's shown prices are at different sizes (or one side's size is unknown and the other's is known and not equal to the flagship default), every SERVER consumer that COMPARES the two amounts (the deterministic verdict price lines, the value / price dimension of the scoring, any "cheaper by" or delta text, the Claude verdict prompt's price inputs, the smart pick if it is server-side) must receive exactly the inputs it receives TODAY in the one-side-pended case, so it says what it says today: no price comparison. The price objects themselves carry their amounts. The spec measures every such consumer (Q5) and picks the smallest seam (one helper that returns "prices comparable: yes / no" read by each consumer, or one projection applied before the consumers run). Per-ml comparison text is NOT added in this unit.

- P2-5 SIZE AND PER-ML ON EVERY SHOWN FRAGRANCE PRICE (X1-R9, X1-R11 carried over). Under the flag every shown fragrance price whose own listing yields exactly one strict size token (X1-R7's parser) carries additive `size_ml` (number) and `per_ml` (round(amount / size_ml, 4), in the price's currency per ml). A pair-level additive marker `metadata.price_basis` = {"mode": "same_size" | "different_sizes" | "unknown", "sizes_ml": [a, b]} (names may be refined by the spec; additive only). INC-X1's `price.offsize_listing` key is NOT built: showing both prices replaces it. X1-R1 holds: the SAME step runs in every build (sync, stream, the verdict-window and moderation-window partials, the stream tail and gather-time partials) and a partial built after the reconcile carries exactly what a full build carries.
