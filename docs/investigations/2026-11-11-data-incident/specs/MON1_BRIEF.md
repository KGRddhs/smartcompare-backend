## 0 What the unit does

The OpenAI credential on the production web service was rejected (HTTP 401) from some time between 2026-10-18 and 2026-10-31 until at least 2026-11-11, and nobody was told. Three things made it silent:

1. The dispatch chokepoint classifies a 401 as "the server answered" and records nothing an operator can see. `_openai_server_answered` (app/services/api_budget_service.py:894-908) returns True for every 4xx except 429; `_openai_failure_is_transient` (:911-938) returns False for it; the except arm of `guarded_llm_create` (:1031-1042) therefore records no failure. That is correct for GATING (a dead credential must not trip a breaker that gates every compare, W1-3b) and wrong for ALERTING.
2. `/health` (app/main.py:626-648) carries no LLM state and no Serper state. It has the precedent this unit follows: `brightdata_auth` {last_status, at}, present only after a 401 / 403 from Bright Data in this process (main.py:333-337; brightdata_service.py:55-95), merged through `_module_snapshot` (main.py:313), a `sys.modules` read that never imports and never raises.
3. Each failing call raised an ERROR record (a Sentry event through `LoggingIntegration(level=logging.ERROR)`, sentry_service.py:738), 48 events since 2026-10-31, and no alert rule notified anyone. There was no single, low-volume, clearly named event to hang a rule on, and the uptime monitor requests only the root path.

MON1 adds the operator-visible signal: a credential-state recorder at the dispatch chokepoints, one alert-grade event per state change, the state on `/health`, a monitor path that answers non-200 while a credential is known rejected, the Serper key counts, and a dark active check so a dead credential is seen with no user traffic (production traffic is about two comparisons a week, so a passive signal alone would have fired only on 2026-10-31).

## 1 THE FLAG RULING (R-MON1-1): a split

- (a) PASSIVE PART, UNFLAGGED. The recorder, the alert event, the `/health` entries and the monitor path ship without a flag, as a production bug fix whose OFF path is the defect (root cause 2). Reasons: the change is additive (no response key any client reads; `/health` is additive by its own docstring rule; the new event fires only on a state change that today already produces an ERROR event per call); nothing on the compare path changes (no gating, no await, no I/O: dictionary writes inside existing outcome arms); a flag would leave the alarm off by default, which is the incident.
- (b) ACTIVE CHECK, DARK. New flag `ENABLE_LLM_CREDENTIAL_PROBE` (default OFF, read per tick with the house idiom) and the knob `LLM_CREDENTIAL_PROBE_INTERVAL_SECONDS` (default 900; defensive parse: unset, garbage, inf, nan, <= 0 fall back; a floor of 300). It adds outbound calls from the web process, so it gets its own canary window.
- What the owner is told changes on the deploy of this unit (sent to the relay; the spec keeps this list exact): `/health` may show two new entries; one new Sentry event the first time a provider credential is rejected in a process, and one when it recovers; a new read-only path for an uptime monitor; nothing else. The compare responses, the gating and the timings are byte-identical.

## 2 Scope rulings (binding on the spec; the spec may refine names, never widen)

- R-MON1-2 GATING IS UNCHANGED. `_openai_server_answered`, `_openai_failure_is_transient`, the breaker blob, the half-open probe logic and `llm_router._classify` stay byte-identical; a 401 / 403 never counts as a breaker failure and never denies an admission. PIN rows prove it with the FULL configuration (B1 rule) with ENABLE_LLM_PREFLIGHT_BREAKER OFF and ON and ENABLE_LLM_SPEND_BREAKER OFF and ON.
- R-MON1-3 THE RECORDER is ONE new leaf module (proposed `app/services/llm_credential_health.py`; stdlib only; no import of a service module; a lock; never raises). State per provider from the closed set {openai, anthropic}: `state` in {ok, rejected, quota}, `last_status` (int or null), `at` (UTC ISO timestamp), `source` in {dispatch, probe, moderation}, a count. Functions: note a rejection, note a success, a snapshot for `/health`, a predicate for the monitor path, a test reset that conftest calls per test (the `_reset_serper_key_state_memo` precedent). It never holds or logs a credential, a header, an exception text, a URL or a model output: constants, closed-set names, ints and timestamps only.
- R-MON1-4 CLASSIFICATION is by exception CLASS and `status_code` (and, for quota, the SDK's structured error code attribute), never by message text: an authentication error (401) or a permission error (403) -> `rejected`; the provider's "account out of credit" class -> `quota`; everything else leaves the state alone (a timeout, a 5xx, a plain rate limit and a 400 say nothing about the credential). The spec MEASURES on the pinned openai and anthropic SDK versions (the lock files; never from memory) which classes and attributes carry 401, 403 and the out-of-credit case, and builds the test doubles from the real classes.
- R-MON1-5 HOOK SITES: every provider dispatch in the web process, found by a CENSUS at the base sha, not from this list. Starting points: (1) `guarded_llm_create` (api_budget_service.py:955-1058): the one OpenAI chat chokepoint; all 16 router sites reach it through `llm_router.route` (llm_router.py:1086-1126).
