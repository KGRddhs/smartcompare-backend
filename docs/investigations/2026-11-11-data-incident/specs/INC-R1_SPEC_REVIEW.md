### B3. Non-fragrance pairs are refused (R1-7 (iv) violated; S81-10 pre-empted)
- Mechanism: D10 sets is_fragrance True "when a line or a house matched"; the clause-4 operand `other_is_fragrance = sides[y].resolved or my["is_fragrance"] is True or det[y].is_fragrance is True` lets the deterministic house hit override the model's own verdict for side y.
- Worked example (spec text applied literally): "Gucci Marmont bag" vs "Prada Galleria bag", no chip, consent 3. D-arm: both house-only, medium, is_fragrance True (D10; classify_category_from_text has no "bag" synonym, ES:1183-1233, so the False branch never fires). O-7 skip does not hold (a house matched), so ONE Claude call runs; the model answers is_fragrance false for both (correct). `_outcome`: x=0, mx false, other_is_fragrance = det[1].is_fragrance True -> ASK. The OTA shows "We need clearer names ... Add the brand and the fragrance name." for two bags. Same for "Montblanc Meisterstuck pen" vs "Cartier pen" (x=1 asks through det[0]), "Burberry trench coat" vs "Gucci jacket", and for a residual line hit: "FreeStyle Libre 2" vs "FreeStyle Libre 3" (line Libre matched, residual -> medium, D10 True).
- Flag mix: with ENABLE_FRAGRANCE_ONLY_GATE ON, a house-only non-fragrance pair passes rule 1 at the route ("a KB or fragrance-lexicon positive match proceeds", PLAN_S81 VERIFY corrections) and the ask returns BEFORE post_resolve_refusal (SCS:4496-4510), replacing the honest, budget-metered CATEGORY_NOT_LIVE with an unmetered INSUFFICIENT_DATA.
- Fix: (1) D10: use the lexicon scan the gate already trusts: a house match is a True signal only when `category_gate.scan([name])` reports no non-fragrance term (`evidence` / `not blocked`, CG:362-372); a non-fragrance term with no fragrance-type word gives False. (2) Clause 4: `other_is_fragrance = sides[y].resolved or my["is_fragrance"] is True or (my["is_fragrance"] is None and det[y].is_fragrance is True)` (the model verdict for y wins when it gave one). (3) An explicit (iv): a usable answer with is_fragrance False for both sides and no Fragrances chip -> passthrough. New RED rows: R14 "Gucci Marmont bag" -> is_fragrance False; R22 d15 (bags, model false/false -> passthrough), d16 ("Gucci Marmont" vs "Prada Galleria", false/false -> passthrough), d17 (FreeStyle Libre 2 vs 3 -> passthrough); a mutant per clause.

### B4. Common qualifier words make a correctly typed product unresolvable on BOTH arms, and the pair is then ASKED on consent 3
- Mechanism: GENERIC_WORDS (2.2) is {perfume(s), fragrance(s), cologne(s), scent(s), spray}. Any other extra token stays in core (D4) and in residual (D8) -> UNRESOLVED medium (D9). Guard (d) (2.5) then rejects the model's correct answer, because "every core token outside the window" must be a house token. So "Dior Sauvage for men": D-arm residual [for, men] -> medium; the model returns {Dior, Sauvage, high}; (d): outside tokens [dior, for, men], "for" is not a Dior house token -> rejected. If the other side resolves (any golden name), `_fragrance_intended` clause 1 holds -> ASK; the user who typed the house AND the line gets "Add the brand and the fragrance name".
- The same for "for him", "pour homme", "homme", "men", "man", "tester", "original", "authentic", "new" (all common in GCC fragrance shopping), e.g. "Dior Sauvage EDP 100ml tester", "Bleu de Chanel pour homme". With both sides qualified the pair is guard-rejected twice -> passthrough (R22 d9), so the outcome flips between a refusal and today's unresolved result depending on whether the OTHER side happened to be clean.
- The brief asked for exactly this definition: Q7 "what 'token-wise' means (extra typed tokens; generic words such as 'for men' or 'pour homme'; ...)". R1-6 (d) ("the typed text minus the house words is within the R1-4 edit-distance rule of the returned line, token-wise") does not force "zero extra tokens"; the strict reading is the spec's choice.
- Fix: a closed QUALIFIER set that is (a) dropped from the D8 residual and (b) allowed outside the window in guard (d), but never removed before the line search (so a line whose name holds such a word, e.g. "Dior Homme", still matches its own tokens): for, men, mens, man, male, him, his, homme (and "pour" only directly before "homme"), tester, original, authentic, genuine, new. Gendered-other words stay residual because they name another product (R11 "Creed Aventus for Her" must stay unresolved): her, femme, women, woman, ladies, lady, female (and "pour" before "femme"). New rows: R11b "Dior Sauvage for men" -> resolved (Dior, Sauvage, EDT base); "Bleu de Chanel pour homme" -> resolved; "Creed Aventus for Her" unchanged (unresolved); R21 g12 typed "Tom Ford Ombre Leather for men" + model {Tom Ford, Ombre Leather, high} -> accepted; R22 d18 "Dior Sauvage for men" vs "Chanel Bleu de Chanel EDP" -> resolved, zero creates, no ask; one mutant (the qualifier drop removed) killed by R11b.

### B5. D3 deletes a line's own digit token, so the golden line "Baccarat Rouge 540" cannot resolve when a size is typed with a space
- Measured (probe1, the exported CG.normalize, CG:172-199): "Baccarat Rouge 540 70 ml" -> [baccarat, rouge, 540, 70, ml]; D3 removes "ml" and "the at most two digit tokens directly before" it, i.e. 70 AND 540 -> core [baccarat, rouge]; the alias "baccarat rouge 540" (3 tokens, digits exact) has no window; guard (d) uses the same core, so a correct model answer is rejected too -> ASK when the other side resolves. "Dior Sauvage 3.4oz" -> [dior, sauvage, 3, 4oz]: the "4oz" token is removed but "3" is not "before such a unit token" under the literal reading -> residual [3] -> unresolved; under the other reading "Baccarat Rouge 540 70ml" loses 540 as well. Either reading breaks one common spelling; the RED would freeze it (2.3 is marked "exact").
- Fix: remove exactly the tokens of each size span found in the RAW text by the same patterns extract_size_ml_any uses (_SIZE_ML_RE PS:4073, _SIZE_OZ_RE PS:4099; e.g. "(\d+(?:[.,]\d+)?)\s*(?:-?\s*)(?:fl\.?\s*)?(?:ml|oz)\b"), mapping the span to its normalized tokens; never a digit token outside a span. New rows R06b: "Baccarat Rouge 540 70 ml" -> (MFK, Baccarat Rouge 540, EDP, size 70); "MFK Baccarat Rouge 540 Extrait 70ml" -> Extrait, 70; "Dior Sauvage 3.4oz" -> resolved, size 100; "Dior Sauvage 1.7 fl oz" -> size 50.
