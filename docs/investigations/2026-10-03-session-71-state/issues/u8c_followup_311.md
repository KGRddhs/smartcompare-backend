=== TITLE: Sentry still receives exception text from five other except-arm 5xx sites, the error middleware and the cache logs
=== LABELS: backend,privacy,observability
## Context
U8c (PR #U13PR) de-chained the deletion route so its Sentry 500 event no longer carries the original exception text. The spec survey (an AST walk over `app/api`) and the adversary found these remaining channels, each measured on the pinned sentry-sdk 2.68.1 with an in-memory transport:

1. **Five except-arm 5xx sites** whose own log line or `exc_info=True` already ships the exception text, so `from None` alone would change nothing there: `app/api/auth_routes.py` `update_push_token` (about L1319), `update_reengagement_subs` (about L1404), `update_preference_toggles` (about L1474); `app/api/image_routes.py` (about L318); `app/api/share_routes.py` (about L37) together with `database_service.create_share_token` (a 23505 `details` string can carry a share-link token). Each needs the type-only log fix (the U8b pattern: `type(e).__name__` plus the sqlstate) AND `from None` together.
2. **`ErrorHandlerMiddleware`**: its `f"Unhandled {type}: {exc}"` log with `exc_info=True` ships the text and the full chain of ANY plain exception escaping ANY route, and `from None` cannot help there because Starlette's `BaseHTTPMiddleware` re-chains an escaped exception (`raise app_exc from app_exc.__cause__ or app_exc.__context__`).
3. **`app/services/cache_service.py`** f-string exception logs (`delete_cached` L682 and the others at L161, 183, 198, 209, 221, 310, 313, 414, 417, 496, 499, 533, 561, 580, 583, 655, 883): with Redis down, every account deletion now emits five ERROR events whose text is the Redis exception (host:port, low severity), plus breadcrumbs on the later events.
4. **Transaction spans are not scrubbed**: the sentry-sdk httpx integration records full request URLs (query included) with `sanitize=False`, and `_before_send_transaction` does not touch spans. In production the deletion-path URLs carry the Supabase host and the user UUID, not an email; traces are sampled at 0.1.

## What to build
One unit: apply the U8b/U8c pattern at the five sites and the middleware (type-only text, `from None` where the 500 is raised in-route), route `cache_service` exceptions through `exc_summary` from `app/services/log_scrub.py` (#285), and add span scrubbing (or drop the query) in `_before_send_transaction`. Pin each with the child-process in-memory-transport test of `tests/test_account_deletion_u8c_sentry_chain.py`. Optionally a repo-wide ratchet that every 5xx `HTTPException` raised inside an `except` arm carries `from None`, with an allowlist.
