# I5.3 — Registry dead-domain replacement: control-calibrated liveness evidence

**Date:** 2026-06-11 · **Lane:** I5 "Yield & Wall" (Bundle B S2) · **Decision F:** verify-or-delete, never fabricate.

## Safety rail (dispatcher, binding)

Agent sandboxes on this box can have selective network — a network-blocked curl
reads **identically** to a dead domain, so under verify-or-DELETE a blocked
sandbox would mass-delete LIVE registry rows. Three requirements applied:

1. **Control first.** Curl a known-live control set in the SAME environment
   before any verdict. Controls used: `google.com`, `shopalmoayyed.com`
   (F1.5-verified live 2026-06-10).
2. **"Dead" only if** the control set passes in the same env AND the domain
   fails with **NXDOMAIN / connection-refused** — distinguished from **403**
   (a Cloudflare/bot-defense = ALIVE-but-defended, must NOT be deleted).
3. **Record per-domain evidence** (curl exit code + HTTP status + DNS + env
   note). "Never fabricate" cuts both ways — never fabricate liveness AND never
   fabricate death.

- **REPLACE:** `lulu.com.bh`→`luluhypermarket.com` (all-cat, 3.0); `sharafdg.com.bh`→`bahrain.sharafdg.com` (electronics, 3.0); `extra.com.bh`→`extra.com` (electronics, 3.0). Weights + categories inherited.

## Yield impact (the point of the change)

The electronics Bahrain `limit=4` discovery window was previously
`site:lulu.com.bh OR site:carrefourbh.com OR site:sharafdg.com.bh OR
site:extra.com.bh` — **all four NXDOMAIN**. After I5.3 it is
`site:luluhypermarket.com OR site:bahrain.sharafdg.com OR site:extra.com OR
site:behbehani.com` — **all four alive**, with `bahrain.sharafdg.com` exposing
clean JSON-LD + BHD. `shopalmoayyed.com` remains at index 5 (outside the
limit=4 window) — that is I5.4's job (reorder verified-first OR limit=4→8).
