## What the flag does

`ENABLE_URL_MODE_V2` (default OFF, read per call; a new name, so unset in production by construction). The route reads it ONCE per request and threads a bool down as the conditional kwarg `url_mode_v2=True`.

ON:
- **Pre-gate ($0, before the credit reserve, after the unchanged SSRF 400).** POST/GET `/api/v1/url/compare` refuse a link longer than 2,048 characters (the client's validateUrl bound, `url_routes._URL_V2_MAX_LINK_CHARS`; checked FIRST, before any query parse, reason `url_too_long`, F4-1), a link whose PATH is a storefront root, a search route, a cart/checkout route, an account route or a category/collection listing without a product segment, and a pair equal after normalisation (scheme / host casefold, one leading `www.`, the trailing slash and the fragment dropped, and every query key dropped except the product-route keys with their values: `route=product/product`, `product_id`, `id_product`, `product` and the osCommerce `products_id`, keys case-insensitive, values percent-decoded and stripped; F3-1, so two products of ONE query-routed store are not the same url, a tracking-only difference still is; each link's query is parsed ONCE per request for both the class and the key, `url_pre_gate_view`, F4-1): HTTP 400 `code: NOT_PRODUCT_PAGE` + additive `field` (url1|url2|both) + `reason` (url_too_long|homepage|search|cart|account|category|same_url). Nothing reserved, nothing fetched, no search_logs row (the SSRF-400 class). A root or `/index.*` path whose QUERY names a product route is NOT a homepage (F2-1, narrowed by F3-2 / F3-4, widened by F4-3): an explicit, key-case-insensitive allow-list of an OpenCart `route` whose value is exactly `product/product` (case-insensitive; the listing routes `product/category`, `product/search`, `product/compare`, `product/special` and `product/manufacturer` stay a homepage, refused at $0, unless the link also carries a non-empty `product_id` / `id_product` / `product` / `products_id`, in which case it is exempt and fetched, a cart route such as `/?route=checkout/cart&product_id=5` too, and a cart page is then refused only after the paid LLM rung), `product_id`, a PrestaShop `id_product`, a WooCommerce `product` and an osCommerce / Zen Cart `products_id` key (F4-3; Zen Cart's default PDP url is `index.php?main_page=product_info&products_id=N`), each with a non-empty value (an empty `product_id=` / `product=` is no marker); a tracking-only query (`?gclid=`, `?gbraid=`, `?utm_source=`, `?fbclid=`) stays a homepage, and a bare `p` (a WordPress post id) and an ASP.NET `pid` are deliberately absent.
- **Typed post-fetch outcomes.** A second fetch function `_fetch_page_v2` keeps the last status and the final url (`fetch_page` is byte-unchanged): transport error / SSRF-blocked initial url or hop / the redirect cap (at most five requests: four followed hops, as `fetch_page`) / non-2xx / a challenge page judged on the start of its FIRST `<title>` -> 400 `STORE_UNREADABLE`; the title is read by a linear `str.find` scan of the first 64 KiB only (pinned F3-5; an unclosed title up to 1,024 characters), F2-2 having replaced a quadratic regex. A final url in any pre-gate class -> 400 `NOT_PRODUCT_PAGE` with that class as the reason (GC-2; the F2-1 exemption applies there too). No Product node (JSON-LD shape ladder; the first node in document order is used) and no usable title (the meta title is the first USABLE of og:title and the `<title>` tag, F4-4, so an og:title equal to the site name or a placeholder no longer shadows a usable `<title>`; unusable = empty, a placeholder, or equal to an Organization / WebSite name or og:site_name; a WebPage node's name is not a site name) -> 400 `UNRESOLVED_PRODUCT` with no LLM call; the LLM's `is_product_page: false` refuses only a node-less page, `null_name` only an unusable title (B4-R1). A delivered `products[i].name` is never a placeholder or the site's own name (F2-5): a Product node whose name is missing or unusable takes that first usable meta title (decided on the value, not on key presence; a nameless node with a price now delivers at $0 with no LLM call), an unusable merged LLM name gives way to the usable title, the title is the first USABLE of the page title and the LLM's `full_title` (a placeholder-named or site-named node no longer shadows a usable `full_title`, F3-3), and with no usable title the link is `UNRESOLVED_PRODUCT` `null_name`. A 25 s `asyncio.wait_for` -> the structured 503 `TIMEOUT`. Precedence STORE_UNREADABLE > NOT_PRODUCT_PAGE > UNRESOLVED_PRODUCT with `field: both` and the reason of the first link carrying the chosen code; an exception inside `extract_from_url` keeps the base codeless 400.
- **Non-delivery (R-A3)** through the existing coded-failure exit: refund once (`usage_refund.url.compare.failure`), no lifetime bump, no history row, the W4-13 failure row with the code's constant message.
- **Envelope.** The error handler passes `field` / `reason` (str only) through for the three B4 codes only (B4-R5).
- **Images.** `image_url` = the first absolute https url string (JSON-LD `image` via `price_service._jsonld_image_urls`, `@graph` / `@type` lists / `ProductGroup.hasVariant` via the shape ladder, `urljoin` on the FINAL url, the og:image key-presence bug fixed) or null; an image that reaches the normaliser raw (the noon / amazon extractors' base bodies, an LLM-merged list) is coerced the same way. A deliberate retype from the raw JSON-LD list on fragrancex-class pages (PLAN section 0 item 4).
- **Why we chose.** The frozen keys `recommendation` (from `strip_score_internals(winner_reason)` with the `_QUALITATIVE_WINNER_REASON` fallback) and `key_differences` (the `specs_comparison` advantages) are filled; the top-level key set is unchanged and there is still no `metadata` (Link compares stay unpersisted, R0-1).
- **Prompt.** `URL_EXTRACTION_PROMPT_V2` asks for `is_product_page`; derived from the untouched V1 by two count-checked swaps; same render shape and kwargs `{gpt-4o-mini, 800, 0.1, store False}`.
- **Logs** (constants, ints, exception type names and hosts only): INFO `[URL-V2] refused code= field= reason=`; INFO `[URL-V2] outcome= reason= status=` once per fetched link; `[URL-V2] fetch failed host= reason= type=` once per unreadable fetch, at **ERROR for a transport error** (`reason=fetch_error`, logged inside `_fetch_page_v2`'s except arm with the exception TYPE; F4-1, amending GC-1) and at WARNING for a blocked initial url or hop, the redirect cap, a non-2xx or a challenge page (`type=None`); the base `Failed to fetch URL host` ERROR template is never reused (it stays the one ERROR call with that prefix, the u8d R8 pin); WARNING `[URL-V2] deadline 25.0s hit`; the v2 fetch's `[SSRF]` WARNING lines print the host only. Pinned (F2-4a): over a pasted link carrying userinfo, a path token and a query token, no record of any logger (root at DEBUG) carries any of them on any unreadable outcome; the transport ERROR record carries no exception info, exception text or stack info (pinned F3-5 on that record), and no record of the run carries exception info. A 401 is `http_4xx` (pinned F3-5). `extract_with_ai`'s ERROR line is `AI extraction error: <ExceptionType>` on both paths (F4-5, unflagged, below).
- **Sentry consequence (F2-6 a, the cause per F3-6; read from the code, not from a Sentry canary).** An ERROR log record becomes a Sentry event through the default `event_level=logging.ERROR` of the `LoggingIntegration` that `sentry_service` installs (sentry-sdk 2.68.1, `integrations/logging.py` `DEFAULT_EVENT_LEVEL`; its `level=logging.ERROR` argument, `sentry_service.py:736` at this HEAD (`:651` at the spec base, before B1 #364 added 88 lines above it; the CLAUDE.md row still cites `:651`), sets only the breadcrumb level), so with the flag ON a link transport error is a Sentry event under the `[URL-V2] fetch failed` template (it replaces the base `Failed to fetch URL host` event of the OFF path, so the count is unchanged for transport errors), while a non-2xx link (the V02 fragrancex class), an ERROR event at base through `raise_for_status`, becomes a WARNING and no Sentry event; its counters are the `[URL-V2] outcome=http_error` INFO line and the search_logs failure row.

UNFLAGGED (R-A1 b, log-only): the INFO lines `URL comparison request`, `URL extraction request` and `Detected retailer` print the host only (the retailer label is a SUPPORTED_RETAILERS name or `unknown`, never the raw netloc; pinned F2-4c with a userinfo + port link on the base path and the v2 path); and `extract_with_ai`'s ERROR line (reachable with the flag OFF and ON) is `AI extraction error: <ExceptionType>`, the exception TYPE only, where it logged the exception text (F4-5, the round-3 engineering e-m6, the U8d class; the returned `{"error": str(e)}` is unchanged, pinned by `test_extract_with_ai_error_line_carries_the_type_only[base|v2]` with a run-time sentinel in the raised message).

OFF: byte-identical (base positional call, no pre-gate, no deadline, `fetch_page`, the base prompt, the raw `image_url`, `recommendation ""` / `key_differences []`, the four-key envelope). The only OFF deltas: one env read per request in the route and one per error response, the import-time derived prompt constant, four defaulted kwargs (non-wire). Every fix-round-2 code change sits in a function only the flagged path reaches (`classify_url_path`, `_is_challenge_page`, `extract_generic_data_v2`, `_extract_from_url_v2`); so does every fix-round-3 change (`normalize_url_for_same_check`, called only by the flagged pre-gate; `_query_names_a_product_route` and the new `_product_route_pairs`, reached only through `classify_url_path` and that key; `_extract_from_url_v2`), plus the import of `urlencode` (import time, no behaviour); and so does every fix-round-4 change (the length bound inside `url_routes._url_pre_gate`; the new `url_pre_gate_view`, called only by it; the keyword-only `pairs=None` parameter on `classify_url_path` and `normalize_url_for_same_check`, both called only by flagged code; `products_id` in `_PRODUCT_ROUTE_QUERY_KEYS`, read only through `classify_url_path`; the first-usable meta title inside `extract_generic_data_v2`), except the unflagged, log-only F4-5 line.

Build 3: every new 400 code renders the generic copy (`errorCopy.ts` default arm) exactly as the codeless 400 today; the 503 TIMEOUT renders the timeout copy. C3 maps `field` / `reason` after approval.
