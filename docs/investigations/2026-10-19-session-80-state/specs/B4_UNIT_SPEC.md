## 0. What the unit does (one paragraph)

Behind `ENABLE_URL_MODE_V2` (default OFF, read per call): POST and GET `/api/v1/url/compare` refuse, for $0 and BEFORE the credit reserve (the SSRF-400 position), a link whose path is a storefront root, a search route, a cart or checkout route, an account route or a category listing, and a pair that is the same URL after normalisation (scheme and host casefolded, a leading `www.` dropped, the trailing slash dropped, query and fragment dropped), with HTTP 400, `code: NOT_PRODUCT_PAGE`, and the additive keys `field` (`url1` | `url2` | `both`) and `reason` (`homepage` | `search` | `cart` | `category` | `account` | `same_url`); nothing is reserved, nothing is written to `search_logs` (exactly like the SSRF 400). After the fetch, every outcome carries a code so the error handler keeps it: a transport failure, a non-2xx status or a challenge page is `STORE_UNREADABLE`; a page with no schema.org Product node and no usable title, or an LLM answer with `is_product_page: false` or a null name, is `UNRESOLVED_PRODUCT` (never `success: true` with `Unknown Product`); a redirect whose final URL is a storefront root or search route is `NOT_PRODUCT_PAGE` post-fetch; and a 25 s `asyncio.wait_for` around `compare_from_urls` yields `code: TIMEOUT`, which the shared text-route mapping ships as the structured 503 build 3 already maps. Every one of these is a non-delivery per R-A3 through the existing coded-failure exit of `_compare_urls_metered`: the reserved credit is refunded once, the lifetime RPC and the history save never run, and under `ENABLE_SEARCH_LOG_TRUTH` the row is today's failure row shape with the code's constant message. Under the same flag the URL extractor normalises images (JSON-LD `image` through `price_service._jsonld_image_urls`, Product nodes found through the shape ladder incl. `@graph`, `@type` lists and `ProductGroup.hasVariant`, `urljoin` against the FINAL url, https only, the `og:image` key-presence bug fixed) so `image_url` is a string or null on the wire, fills the frozen keys `recommendation` (from `strip_score_internals(comparison.winner_reason)` with the existing qualitative fallback) and `key_differences` (from `specs_comparison` advantages) without adding a top-level key, and asks the extraction LLM for `is_product_page` through a SECOND prompt constant `URL_EXTRACTION_PROMPT_V2` selected per call (R0-6). Unflagged, per R-A1(b): the INFO lines that print the pasted URLs print the host only. No Chrome impersonation on the URL path (R-A7): fragrancex stays unreadable and is recorded as `STORE_UNREADABLE`. Flag OFF: no pre-gate, no second fetch function, no deadline, no prompt change, no image or key change, the SSRF 400 and the `Could not extract both products` 400 byte-identical, the W4-13 flag-OFF ledger byte-identical.

## 11. Open questions for the orchestrator

- Q1 (envelope keys): this spec carries `field` / `reason` through `error_handler.http_exception_handler` with a flag-gated additive passthrough (inert for every existing route: no detail carries the keys today). Alternative: return a `JSONResponse(400, {...})` from `url_routes` directly and leave the middleware untouched (one fewer file, a second envelope builder with `request_id`). Recommended: the passthrough (one envelope builder, the brief's "raised with a code").
- Q2 (reason vocabulary): R-A7 lists `homepage|search|cart|category|same_url`; the brief also names account paths. This spec adds `account` and the post-fetch reasons `fetch_error|blocked|redirect_cap|http_403|http_4xx|http_5xx|http_3xx|challenge|no_product_node|not_product_page|null_name`. Recommended: accept (C3 reads `code` first and `reason` only for copy nuance). Alternative: fold `account` into `cart` and drop the post-fetch reasons.
- Q3 (deadline knob): a module constant 25.0 with a seam vs an env knob `URL_COMPARE_DEADLINE_SECONDS` (defensive parse). Recommended: the constant (the brief says 25 s; the client cap is fixed at 35 s; fewer rows). Alternative: the knob, adding a reader table and three rows.
- Q4 (the third INFO line): `url_routes.py:294` (`/extract`, admin-only) also prints the full url; this spec includes it in the unflagged host-only change (R-A1 b). Confirm or restrict to the two lines the brief names.
- Q5 (precedence of mixed codes): STORE_UNREADABLE > NOT_PRODUCT_PAGE > UNRESOLVED_PRODUCT with `field both`. Alternative: the first url's code. Recommended: precedence (the most actionable cause wins).
- Q6 (ItemList pages): a page carrying Product nodes inside an ItemList (the sephora fixture) delivers today and under ON; the LLM's `is_product_page: false` is ignored when a node exists. Alternative: let `false` override a node-bearing page (risks refusing real PDPs whose JSON-LD also lists related products). Recommended: keep the node rule.
- Q7 (the W0-4 parse-offload interaction): `extract_generic_data_v2` runs through the same `run_parse_offloaded` when `ENABLE_PRICE_PARSE_OFFLOAD` is on (production); R19 is run in both parse-flag states. Confirm this is sufficient, or require a W0-4-style thread pin for the v2 extractor.
- Q8 (the `details` key): the coded `<2 products` dict keeps today's `details` list (dropped by the route). Confirm (harmless) or drop.
