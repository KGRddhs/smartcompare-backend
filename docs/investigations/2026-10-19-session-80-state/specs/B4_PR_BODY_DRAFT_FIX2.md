## What the flag does

`ENABLE_URL_MODE_V2` (default OFF, read per call; a new name, so unset in production by construction). The route reads it ONCE per request and threads a bool down as the conditional kwarg `url_mode_v2=True`.

ON:
- **Pre-gate ($0, before the credit reserve, after the unchanged SSRF 400).** POST/GET `/api/v1/url/compare` refuse a link whose PATH is a storefront root, a search route, a cart/checkout route, an account route or a category/collection listing without a product segment, and a pair equal after normalisation: HTTP 400 `code: NOT_PRODUCT_PAGE` + additive `field` (url1|url2|both) + `reason` (homepage|search|cart|account|category|same_url). Nothing reserved, nothing fetched, no search_logs row (the SSRF-400 class). A root or `/index.*` path whose QUERY names a product route is NOT a homepage (F2-1): an explicit, key-case-insensitive allow-list of an OpenCart `route` value starting `product/`, `product_id`, a PrestaShop `id_product` and a WooCommerce `product` key; a tracking-only query (`?gclid=`, `?gbraid=`, `?utm_source=`, `?fbclid=`) stays a homepage, and a bare `p` (a WordPress post id) is deliberately absent.
- **Typed post-fetch outcomes.** A second fetch function `_fetch_page_v2` keeps the last status and the final url (`fetch_page` is byte-unchanged): transport error / SSRF-blocked initial url or hop / the redirect cap (at most five requests: four followed hops, as `fetch_page`) / non-2xx / a challenge page judged on the start of its FIRST `<title>` -> 400 `STORE_UNREADABLE`; the title is read by a linear `str.find` scan of the first 64 KiB (an unclosed title up to 1,024 characters), F2-2 having replaced a quadratic regex. A final url in any pre-gate class -> 400 `NOT_PRODUCT_PAGE` with that class as the reason (GC-2; the F2-1 exemption applies there too). No Product node (JSON-LD shape ladder; the first node in document order is used) and no usable title (empty, a placeholder, or equal to an Organization / WebSite name or og:site_name; a WebPage node's name is not a site name) -> 400 `UNRESOLVED_PRODUCT` with no LLM call; the LLM's `is_product_page: false` refuses only a node-less page, `null_name` only an unusable title (B4-R1). A delivered `products[i].name` is never a placeholder or the site's own name (F2-5): a Product node whose name is missing or unusable takes a usable `<title>` / og:title (decided on the value, not on key presence; a nameless node with a price now delivers at $0 with no LLM call), an unusable merged LLM name gives way to the usable title, and with no usable title the link is `UNRESOLVED_PRODUCT` `null_name`. A 25 s `asyncio.wait_for` -> the structured 503 `TIMEOUT`. Precedence STORE_UNREADABLE > NOT_PRODUCT_PAGE > UNRESOLVED_PRODUCT with `field: both` and the reason of the first link carrying the chosen code; an exception inside `extract_from_url` keeps the base codeless 400.
- **Non-delivery (R-A3)** through the existing coded-failure exit: refund once (`usage_refund.url.compare.failure`), no lifetime bump, no history row, the W4-13 failure row with the code's constant message.
- **Envelope.** The error handler passes `field` / `reason` (str only) through for the three B4 codes only (B4-R5).
- **Images.** `image_url` = the first absolute https url string (JSON-LD `image` via `price_service._jsonld_image_urls`, `@graph` / `@type` lists / `ProductGroup.hasVariant` via the shape ladder, `urljoin` on the FINAL url, the og:image key-presence bug fixed) or null; an image that reaches the normaliser raw (the noon / amazon extractors' base bodies, an LLM-merged list) is coerced the same way. A deliberate retype from the raw JSON-LD list on fragrancex-class pages (PLAN section 0 item 4).
- **Why we chose.** The frozen keys `recommendation` (from `strip_score_internals(winner_reason)` with the `_QUALITATIVE_WINNER_REASON` fallback) and `key_differences` (the `specs_comparison` advantages) are filled; the top-level key set is unchanged and there is still no `metadata` (Link compares stay unpersisted, R0-1).
- **Prompt.** `URL_EXTRACTION_PROMPT_V2` asks for `is_product_page`; derived from the untouched V1 by two count-checked swaps; same render shape and kwargs `{gpt-4o-mini, 800, 0.1, store False}`.
- **Logs** (constants, ints, exception type names and hosts only): INFO `[URL-V2] refused code= field= reason=`; INFO `[URL-V2] outcome= reason= status=` once per fetched link; `[URL-V2] fetch failed host= reason= type=` once per unreadable fetch, at **ERROR for a transport error** (`reason=fetch_error`, logged inside `_fetch_page_v2`'s except arm with the exception TYPE; F4-1, amending GC-1) and at WARNING for a blocked initial url or hop, the redirect cap, a non-2xx or a challenge page (`type=None`); the base `Failed to fetch URL host` ERROR template is never reused (it stays the one ERROR call with that prefix, the u8d R8 pin); WARNING `[URL-V2] deadline 25.0s hit`; the v2 fetch's `[SSRF]` WARNING lines print the host only. Pinned (F2-4a): over a pasted link carrying userinfo, a path token and a query token, no record of any logger (root at DEBUG) carries any of them on any unreadable outcome.
- **Sentry consequence (F2-6 a; read from the code, not from a Sentry canary).** `sentry_service` installs `LoggingIntegration(level=logging.ERROR)`, so with the flag ON a link transport error is a Sentry event under the `[URL-V2] fetch failed` template (it replaces the base `Failed to fetch URL host` event of the OFF path, so the count is unchanged for transport errors), while a non-2xx link (the V02 fragrancex class), an ERROR event at base through `raise_for_status`, becomes a WARNING and no Sentry event; its counters are the `[URL-V2] outcome=http_error` INFO line and the search_logs failure row.

UNFLAGGED (R-A1 b, log-only): the INFO lines `URL comparison request`, `URL extraction request` and `Detected retailer` print the host only (the retailer label is a SUPPORTED_RETAILERS name or `unknown`, never the raw netloc; pinned F2-4c with a userinfo + port link on the base path and the v2 path).

OFF: byte-identical (base positional call, no pre-gate, no deadline, `fetch_page`, the base prompt, the raw `image_url`, `recommendation ""` / `key_differences []`, the four-key envelope). The only OFF deltas: one env read per request in the route and one per error response, the import-time derived prompt constant, four defaulted kwargs (non-wire). Every fix-round-2 code change sits in a function only the flagged path reaches (`classify_url_path`, `_is_challenge_page`, `extract_generic_data_v2`, `_extract_from_url_v2`).

Build 3: every new 400 code renders the generic copy (`errorCopy.ts` default arm) exactly as the codeless 400 today; the 503 TIMEOUT renders the timeout copy. C3 maps `field` / `reason` after approval.
