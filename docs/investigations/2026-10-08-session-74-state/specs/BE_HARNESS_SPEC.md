## 2. The A1.8 rule (pass_rule) and the shapes it must reject
`evaluate_compare(http_status, body)` -> `{verdict, reasons, ...}`; reasons are stable ids, checked in this order:
- R1 `http_<n>`: status != 200 -> FAIL, stop (add `code` from the envelope when present).
- R2 `non_json`: body is not a JSON object -> FAIL, stop.
- R3 `not_success`: `body["success"] is not True` (catches the 200 CONTENT_UNAVAILABLE body).
- R4 `comparison_missing` (`comparison` not a dict) / `comparison_error` (`comparison.get("error")` truthy; truthiness as the R-METER ruling at url_extraction_service.py:664-669).
- R5 `no_winner`: `overview.winner.name` not a non-blank str. R6 `products_shape`: `overview.products` not a list of exactly 2 dicts.
- R7 `no_spec_rows`: `specs.specs_comparison.rows` not a non-empty list (a 2-key `specs` dict with `rows: []` FAILS; see BE-01 trap below).
- R8 `no_pros` / `no_cons`: for EACH product i in 0,1, `overview.products[i].pros` / `.cons` holds >= 1 non-blank str.
- R9 `retailer_without_amount`: any product that names a retailer lacks a positive amount. A retailer exists iff a non-blank str sits at `overview.products[i].price.retailer`, `products[i].price.retailer` or `products[i].retailer` (the only wire fields that carry one; every pend path strips all three, section 1). Positive amount = `isinstance(a, (int, float)) and not isinstance(a, bool) and math.isfinite(a) and a > 0`, read at `overview.products[i].price.amount`.
- R10 `no_price_amount` (SOFT): neither product has a positive amount (runbook line 110 "at least one price amount non-null").
- Verdict: FAIL if any reason other than R10; NO_PRICE if R10 is the only reason; PASS if none.
"A price amount on each product that has a retailer" = R9 AND R10: R9 alone is vacuous on an all-pending pair (no retailer field survives a pend), so R10 is what rejects the canary 1-3 200s.
`evaluate_stream(http_status, lines)`: S1 `http_<n>`; S2 `stream_no_terminal` (no settle_complete/complete/error frame); S3 `stream_error_event` (last terminal frame is `error`); S4 `stream_terminal_not_success` (last terminal `data.success is not True`). PASS iff none. Lines starting with ":" are ignored.
BE-01 traps (old script, docs/.../verify_after_credits.py): `has_verdict = bool(d.get("verdict") or ov.get("winner"))` (:38) is True on every built 200 (no `verdict` key exists; `overview.winner` is always a non-empty dict); `specs_rows = len(d.get("specs"))` (:37) counts the 2 dict keys, so every "specs_rows": 2 in the four logs carries no information; pass = `http==200 and success and has_verdict` (:67); stream = `events > 0` (:68); no product_a/product_b request at all.
