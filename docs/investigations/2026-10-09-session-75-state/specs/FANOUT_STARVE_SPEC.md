## 3. The q-form asymmetry (F5), from code
Real, with one deterministic cause and one second-order cause. (i) Serial LLM stage: the q path awaits parse_product_query :3846-3848 inside the cap with no own timeout and no cache (extraction_service.py:1512 has no Redis read; the client is the 120 s / 30 s-connect singleton :76-80, max_retries 1 on web) BEFORE any product work starts; the explicit_pair path :3829-3845 does none of that. The budget available to the gather is therefore 30 - t_parse on q and 30 on the probe; nothing after Step 1 differs by form except identity. (ii) Identity: the parser emits brand + name + variant + search_query (prompt :114/:125, e.g. "Apple iPhone 15") and an authoritative LLM category (:455-466); the explicit path sends the raw string with brand "" and a keyword category. Different Serper queries, different adapter sets, different cache keys (get_specs_cache_key(brand, name, variant) extraction_service.py:2787, get_price_cache_key(brand, name, variant, region) :2806) - moot for freshness under nocache but a different compare. Refuted: no extra credit, prefs, auth, limiter or DNS step on the q form; the category escalation LLM (classify_category_llm :476) is reachable only on the explicit path. Not provable from code: that t_parse alone pushes the gather past 30 s (canary 6 is one sample per form; the canary pairs also differ in text: "Galaxy S24" vs "Samsung Galaxy S24"). Section 6 measures t_parse directly.
Candidate fix (flag, default OFF): `ENABLE_PARSE_BUDGET` + knob `PARSE_TIMEOUT_SECONDS` (default 6.0; non-finite / <= 0 / garbage -> 6.0). New `async def _parse_with_budget(self, query)` in scs: flag OFF -> `return await parse_product_query(query)` (the exact call of :3848; byte-identical result and cost); flag ON -> `asyncio.wait_for(parse_product_query(query), timeout)`; on TimeoutError -> the deterministic split of `query` on the first " vs " (case-insensitive, both halves non-empty) built EXACTLY like :3829-3845 (sanitize_prompt_input max 80, brand "", classify_category_from_text), `parsed = {"comparison_type": "value", "_parse_fallback": True}`; the orchestrator then sets `metadata.parse_fallback: true` (additive key, flag ON only); no " vs " -> the existing parse-failure body :3850-3856. Both states log ONE INFO `[STAGE] parse done elapsed_ms=%d fallback=%s` (logging only; R-W18 class, unflagged; no query text). The flip is gated on the section-6 reading: flip only if the measured t_parse on the q rows is >= 2 s at p50.

## 4. Design
D1 Executor code truth (UNFLAGGED, F1 configuration clause). executor.py:30 `_DEFAULT_MAX_WORKERS = 96`; precedence unchanged: `ADAPTER_EXECUTOR_MAX_WORKERS` int > 0 wins (:35-37), anything else (unset, "0", "-1", "abc", "96.0" -> ValueError) -> 96. Production effect nil: web sets 96 and the env wins; the proof is the test row T1 plus the boot line `[executor] default ThreadPoolExecutor installed: max_workers=96` (:56) unchanged in shape. Docstring :1-18 rewritten (sizing: ~30 blocking fetches per compare measured 2026-10-08; 96 = 3 compares). Additive `executor_snapshot() -> {"adapter_executor": {"workers": n, "queued": pool._work_queue.qsize()}}` (W0-4g precedent price_service.py:4346-4360) spread into /health (main.py:549-552), present only once the pool is installed, no I/O.
D2 Resolver decision. REJECTED `--loop asyncio`: under asyncio `BaseEventLoop.getaddrinfo` runs socket.getaddrinfo on the loop DEFAULT executor, which main.py:179-182 makes the qaren-worker pool, so DNS would queue behind the ~30 curl fetches (the F2 trap; pinned by T5). REJECTED a dedicated httpx resolver: httpx 0.28 / httpcore 1.0.9 expose no resolver hook; the only seam is anyio's backend getaddrinfo (process-global monkeypatch) or a uvloop.Loop subclass + a custom loop factory, both unmeasurable here (F2). ADOPTED: keep uvloop; make UV_THREADPOOL_SIZE code truth in the START COMMAND, the one placement that is provably before libuv's first threadpool use because it precedes the interpreter: railway.json deploy.startCommand and Procfile web: become `exec env UV_THREADPOOL_SIZE="${UV_THREADPOOL_SIZE:-64}" uvicorn app.main:app --host 0.0.0.0 --port $PORT --timeout-graceful-shutdown 20 --limit-concurrency "${UVICORN_LIMIT_CONCURRENCY:-512}"` (quoted retunable form = the W1-7 measured pattern; env override wins; both files byte-equal per tests/test_start_command.py). Not adopted: `os.environ.setdefault` in app/main.py - import happens after uvicorn created the loop and I cannot show here that nothing touched the libuv threadpool before that line (UNVERIFIED, F2). UNFLAGGED by the F1 clause (web already sets 64; nil effect). Boot truth line in main.py startup (logging only): `[loop] class=%s uvloop=%s UV_THREADPOOL_SIZE=%s` with the env VALUE or "unset" (a non-secret integer knob).
D3 Bounded fan-out (FLAG `ENABLE_ADAPTER_FANOUT_BOUND`, default OFF, read per call via os.getenv in `fanout_bound_enabled()` in executor.py, the price_service.exact_gate_enabled idiom :4293-4297). Knob `ADAPTER_FANOUT_MAX_CONCURRENT`: default `max(1, default_executor_size() - 8)` (8 threads reserved for run_db / _cache_*_async / record_usage so a saturated fan-out can never starve the offload class), clamp 1..default_executor_size(), garbage/non-finite -> default, read when the per-loop semaphore is first built (W0-4 precedent price_service.py:4394-4399; a change needs a restart, documented). New `async def run_blocking(fn, /, *args, **kwargs)` in executor.py: flag OFF -> `return await asyncio.to_thread(fn, *args, **kwargs)` with no semaphore read, no getenv beyond the flag; flag ON -> `async with _fanout_semaphore(): return await asyncio.to_thread(...)` (acquire BEFORE submit, so waiters queue in asyncio, not in the executor; a wait_for cancel while waiting removes the waiter and holds nothing; a cancel while holding releases in `async with` finally and the thread runs on as today). Rerouted sites = the adapter-fetch class only: price_service.py curl_fetch_html :14764, curl_fetch_html_same_site :14852, :15172, :15215, :16209, :16421 (NOT :4434, the parse pool), magento_graphql_service :441 :485 :519 :648, algolia_service :243 :259 :305 :353, rest_json_service :267 :325 :410, woocommerce_service :340 :346, salla_service :97 :211, unbxd_service :195, shopify_pdp_service :340, occ_service :285, noon_service :170, sitemap_discovery_service :416 (26 sites; the implementer confirms each wraps a network fetch; yotpo_service :261 and spec_spine_service :310 are off-path and stay as they are; the offload class - usage_service, auth_service, home_routes, db_offload, serper_service :47 record_usage, review_service, feedback_service, scs :1101/:1116/:1155/:1170 (_cache_*_async Redis offload) - is never rerouted). Deadlock argument: a slot is held only around one sync fn that cannot await, so no holder ever waits on another slot; bound < pool size leaves threads for the offload class; no nested acquisition exists (AST pin T9c).
