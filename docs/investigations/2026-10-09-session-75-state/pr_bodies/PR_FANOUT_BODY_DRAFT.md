## FANOUT-STARVE: the fan-out's starvation points named, bounded and observable (four dark flags + configuration truth)

Spec, review, rulings and gate records: `docs/investigations/2026-10-09-session-75-state/specs/FANOUT_STARVE_{SPEC,REVIEW}.md`, `FABLE_RULINGS_FANOUT_STARVE.md` (FS-R1..R20), `FABLE_REVIEW_RED_FANOUT_STARVE.md` (FG-1..FG-10), `FABLE_RULINGS_FANOUT_STARVE_POST_ADVERSARY.md` (FY1-FYn).

### Why
Canaries 3-6 (sessions 74) showed the compare's own fan-out starving itself on the single uvicorn worker: ~30 blocking adapter fetches per compare against a 40-thread default executor (adapter TIMEOUT drops were the queue), Serper `ConnectTimeout`s whose 3 s connect budget expired on uvloop's 4-thread DNS pool rather than on the network, an unbounded unified search sitting on the product wall, Phase 2 running into the hard cap, and a Bright Data token that expired in production without one Sentry event. The web service has carried the tuned values since 2026-10-08; this unit makes them code truth and adds the bounds behind flags. Acceptance (FS-R1) is app-shaped rows (`product_a` / `product_b`), the form the phones send.

### What this does
- **Unflagged (configuration truth + observability, flag-OFF byte-identical on every response):** `ADAPTER_EXECUTOR_MAX_WORKERS` default 40 -> 96 (`app/utils/executor.py`; web has run 96 since 2026-10-08); the Serper fail-fast connect default 3.0 -> 8.0 s (`SERPER_CONNECT_TIMEOUT`, web since 2026-10-08); the start command (`railway.json` + `Procfile`, byte-identical pair) runs `exec env UV_THREADPOOL_SIZE="${UV_THREADPOOL_SIZE:-64}" uvicorn ...` so libuv's DNS pool is sized before the interpreter starts; one `[loop] class=... uvloop=... UV_THREADPOOL_SIZE=...` INFO line at startup proves what took effect; one `[STAGE] parse done elapsed_ms=<int> mode=llm|presplit|fallback` INFO per q-form parse; Bright Data: ONE ERROR per process per status (401 / 403) naming `BRIGHTDATA_API_KEY` (the renewal runbook `docs/runbooks/brightdata-token-renewal.md`), the non-200 WARNING withholds a 401/403 body; `/health` gains `adapter_executor` {workers, queued} on every process that installed the pool and `brightdata_auth` {last_status, at} only after a 401/403 (public endpoint; deliberate, status + timestamp only).
- **Four NEW flags, every one default OFF and read PER CALL:** `ENABLE_PARSE_PRESPLIT` (a q-form query that splits cleanly on its first case-insensitive " vs " takes the app's explicit-pair shape with NO LLM parse call; brand "", keyword category, `parser_path` False, `metadata.parse_presplit`); `ENABLE_PARSE_BUDGET` + knob `PARSE_TIMEOUT_SECONDS` (8.0; a STALL guard on `parse_product_query`: on timeout the same deterministic split, `metadata.parse_fallback`, or today's parse-failure body when the query has no " vs "); `ENABLE_UNIFIED_SEARCH_BOUND` + knob `UNIFIED_SEARCH_TIMEOUT_SECONDS` (12.0; the unified search gets a bound; on timeout specs/reviews receive an explicit EMPTY payload, never None, one WARNING); `ENABLE_PHASE2_RESIDUAL_GUARD` + knob `PHASE2_MIN_RESIDUAL_SECONDS` (8.0; a product closer than that to the compare deadline skips Phase 2 -- the verified rating and the smart-fallback refill -- so the compare reaches scoring and a verdict instead of a gather partial; `metadata.phase2_skipped`). Every knob rejects unset / "" / garbage / nan / inf / <= 0 and falls back to its default.
- **Canary (D9):** `scripts/verify_after_credits.py --form q|pair|both` (default: today's rows byte for byte; `both` runs each curated pair in both forms, the RESULT line ends ` q_fail=<n> pair_fail=<n>`, the q rows drive the exit only under `--strict-q`); `run_canary.sh` passes `--form both` and its fallback classification now accepts the suffixed PASS line (a real defect of the inherited partial, fixed and proven in GREEN).

### Stated limits
- The libuv pool size takes effect only through the start command; proof is the `[loop]` boot line on the first deploy (uvloop is absent on the Windows venv, so the uvloop=True branch is unmeasured here). If the Nixpacks image lacked coreutils `env`, the Railway healthcheck gate would keep the previous deployment; rollback is the one-line revert.
- `price-warmer`: D1 has no effect there (no `install_default_executor`); D4 reaches it only when its cron runs; "once per process" for the Bright Data ERROR means once per warmer run.
- Under `ENABLE_PARSE_PRESPLIT` / `ENABLE_PARSE_BUDGET` a q-form compare trades the LLM identity (brand, variant, full-context category) for the app shape; under `ENABLE_PHASE2_RESIDUAL_GUARD` the skipped product loses its verified rating and refill for that request; under `ENABLE_UNIFIED_SEARCH_BOUND` a timed-out product's specs come from an empty context and its reviews from none (its Serper call is still counted). With every flag OFF, D4 widens the unbounded unified search's worst case from 27 s to 32 s on a 3-key rotation; D5 closes it.
- `run_canary.sh` points at sc-docs-70's copy of `verify_after_credits.py`, which must be at or after this merge or `--form` is an argparse usage error.
