# design-sync notes — Qaren Design System

Project: **Qaren Design System** (`c57eb43f-cabf-47bc-b980-ff4956512b26`) on claude.ai/design.

## This is a hand-authored project — the converter does NOT apply

`SmartCompareApp/` is **React Native + Expo**. It does not render in a browser, and its
components import directly from `react-native`. So this design-system project is **not** a
compiled-`dist/` bundle produced by the `/design-sync` converter (`package-build.mjs`, the
storybook/package shapes). Instead it holds **hand-authored web JSX references** that mirror
the RN screens:

- `ui_kits/mobile/<Screen>.jsx` — a plain-React (web, inline-style) reimplementation that
  reads tokens from `window.qarenTokens` and exports `window.Qaren<Screen>`.
- `ui_kits/mobile/<screen>.html` — a preview card (babel-standalone) that loads the `.jsx`
  inside `ios-frame.jsx` and carries the `<!-- @dsCard … -->` marker the pane indexes.

**A re-sync = diff the RN source-of-truth against the matching `.jsx` reference and integrate
by hand.** Do NOT point the converter at `SmartCompareApp`.

### Results is CATEGORY-DRIVEN (all 9 categories)

`ResultsScreen.jsx` is ONE generic shell + a `CATEGORIES` config covering all 9 Qaren
categories (electronics, grocery, supplements, makeup, skincare, haircare, fragrances,
fashion, other). This mirrors the app exactly: the layout is fixed, the **data** is
per-category. When the per-category structure changes, update it from these backend
sources (NOT invented):

| What | Backend source |
|---|---|
| 6 dims per category + display labels | `app/services/scoring_service.py` `CATEGORY_DIMENSIONS`, `DIMENSION_DISPLAY_NAMES` (bars show the top-4 hero dims) |
| Specs schema + ordered "At a glance" fields | `app/services/extraction_service.py` `CATEGORY_SPEC_SCHEMAS`, `build_category_profile` (At a glance = the populated subset, in schema order) |
| Price-comparability basis (like-for-like unit) | `app/services/price_service.py` `CATEGORY_FAIRNESS` (electronics→GB, fragrances/haircare→ml, supplements→count, grocery/makeup/skincare→weight·vol, **fashion/other→None** → no basis caption) |

Each category has its OWN preview card: `results.html` (Electronics) + `results-<category>.html`,
all loading the shared `ResultsScreen.jsx` via `<QarenResultsScreen category="<key>"/>`. Add a
new category only if `CATEGORY_SPEC_SCHEMAS` gains one (the schema keyset is frozen via
`canonicalize_category()`). Preview cards are regenerated by `.design-sync/staging/_gen_previews.mjs`
(local-only; not uploaded).

## Authoring conventions for the `.jsx` references

- React is a UMD global — use `React.useState`, not a bare `useState` import.
- Style with inline `style={{…}}` + `window.qarenTokens` colors (`C_res.accent`,
  `accentDark`, `accentLight`, `warning`, `text.{primary,secondary,placeholder}`,
  `border.{light,medium}`, `bg.{primary,secondary}`). All exist in the token block.
- Use the **real shipped copy** from `src/i18n/en.json` (e.g. "Why this fits you",
  "Where the runner-up wins", "What we know", "Dig deeper", "At a glance",
  "Pricing lands in an upcoming update."). Copy must pass `src/i18n/.copy-policy.json`.
- Hard invariants to preserve in any results edit: ratings are NEVER AI-generated (stars
  only with a real rating); reviews are PARAPHRASED praise (no verbatim quotes, source
  domains, or `[N]` citations); the runner-up block stays **gray** (emerald = winner signal).
